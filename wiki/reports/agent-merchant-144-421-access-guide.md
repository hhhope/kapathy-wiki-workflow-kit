# 代运营商户协议支付 + 余额分账产品接入指引

> 适用对象：需要为代运营商户完成开户、一次性开通协议支付产品 `144` 和余额分账产品 `421`，并完成绑卡扣款、分账、通知查询和结算验证的接入、产品、运营、技术同事。
>
> 结论先行：本指引以飞书原接入指引为主干，当前客户方案按 `144 + 421` 一次性产品开通处理。产品开通接口同一次请求传入两个 `feeRuleList` 条目，两个产品的 `productModelId` 均使用 `10370560005`。421 补充资料按分账类产品口径判断：不要求传银行类型，不要求传技术支持电话或 `techSupportFlag`；如分账类产品需要补充附件，产品开通附件类型选择 `9915999`。

## 1. 本次接入目标

本次需求不是普通代运营商户只开户，而是要完成一条从开户到交易验证的完整链路：

1. 代运营商户开户进件，获取代运营商户 `uid`。
2. 使用开户返回的 `uid`，一次性开通协议支付产品 `144` 和余额分账产品 `421`。
3. 代运营商户完成协议支付绑卡扣款验证。
4. 分账接收方进件。
5. 分账接收方绑定代运营商户。
6. 从代运营商户余额分账到分账接收方商户。
7. 接收分账通知，并通过分账查询核对结果。
8. 分账接收方次日自动结算，核对银行流水展示口径。

## 3. 推荐接入流程

```mermaid
flowchart LR
  A[代运营开户进件] --> B[获取 uid]
  B --> C[一次性开通 144 + 421]
  C --> D[协议支付绑卡扣款验证]
  C --> E[分账接收方进件]
  E --> F[确认或单独绑定分账关系]
  F --> G[余额分账交易]
  G --> H[分账通知和查询核对]
  H --> I[次日自动结算核对]
```

核心原因是：`uid` 是产品开通的基础；交易闭环还依赖绑卡扣款、分账关系、分账通知/查询和结算口径共同验证。

## 4. 第一步：代运营开户进件

### 4.1 接口用途

先通过代运营开户进件接口创建代运营商户。开户成功后，接口返回 `uid`，后续一次性开通 `144 + 421` 时使用这个 `uid`。

### 4.2 本次关键参数

| 参数 | 本次建议 | 说明 |
|---|---|---|
| `merchantType` | `COMPANY` | 本次样例为企业主体。 |
| `merchantProperties` | `AGENT_MEMBER` | 标识为代运营成员商户。 |
| `createBaseInfo` | 按商户营业执照、法人、地址、联系人信息填写 | 不要在飞书中传递完整身份证、手机号、邮箱等敏感信息。 |
| `cdpMerchantBusinessInfo` | 按经营类目填写 | 包含业务类型、一级/二级类目等。 |
| `cdpMerchantBankInfo` | 按结算账户填写 | 企业商户应确保账户名与主体一致。 |
| `merchantFileInfos` | 上传文件后传文件 UUID | 文件类型和 UUID 以文件上传结果为准。 |
| `notifyUrl` | 按接入方回调地址填写 | 用于接收进件结果通知。 |

### 4.3 开户所需资料

宝付代扣代运营开户资料按当前沟通口径包括：

| 序号 | 资料 | 说明 |
|---:|---|---|
| 1 | 营业执照、对公账户、银行电子回单、法人身份证正反面、手机号、邮箱 | 主体和联系人基础资料。 |
| 2 | 门头照和办公场景照片 | 门头照需包含门牌 logo，办公场景照片 2 张。 |
| 3 | 手机端截图、商家店铺二维码、商家店铺认证页 | 用于证明线上经营场景。 |
| 4 | 代运营协议、委托划扣授权书 | 授权内容需要合规确认，尤其是法人授权表达。 |
| 5 | 推广代付协议 | 按销售和合规要求提供。 |
| 6 | 合作情况说明函 | 按销售和合规要求提供。 |

资料最终必传清单仍以合规准入口径为准。

## 5. 第二步：一次性开通产品 144 + 421

### 5.1 核心结论

本次给客户提供的是 `144 + 421` 一次性产品开通方案。实现上是在同一次产品开通请求中传入两个 `feeRuleList` 条目：

1. 协议支付产品 `144`：`productModelId` 使用 `10370560005`。
2. 余额分账产品 `421`：`productModelId` 同样使用 `10370560005`。
3. 请求中的 `uid` 使用代运营开户返回的商户 `uid`，不要使用父级代理商 UID。
4. 421 的 `prodExtendInfo.openSupplyInfo` 按产品和分账资料口径传入。

### 5.2 421 扩展信息口径

| 参数 | 本次口径 | 说明 |
|---|---|---|
| `prodExtendInfo.bankType` | 不需要传 | 2026-06-23 沟通确认本场景不要求传银行类型。 |
| `openSupplyInfo.techSupportFlag` | 不需要传 | 默认可不传；不要为了凑字段要求客户提供技术支持电话。 |
| `openSupplyInfo.techSupportPhone` | 不需要传 | 当前产品补充信息字段表不要求该字段，本指引不再放入样例。 |
| `openSupplyInfo.shareProdRatio` | 条件必传 | 订单分账产品必传，支持两位小数，取值范围 `(0,100]`；余额分账上传 `100` 即可。 |
| `openSupplyInfo.supplyFiles` | 条件必传 | 分账类产品如果未在开户或会员补充资料阶段送过资料 2 至 6，需要补充上传。产品开通附件类型选择 `9915999`。 |

### 5.3 一次性开通请求结构

```json
{
  "uid": "<代运营开户返回的uid>",
  "applySerialNo": "<产品开通申请流水号>",
  "notifyUrl": "<产品开通回调地址>",
  "signedWay": "2",
  "signedFun": "1",
  "feeRuleList": [
    {
      "productId": "144",
      "productModelId": "10370560005",
      "feeAcctId": "1",
      "billModel": "1",
      "beginEffectiveTime": "<生效时间>",
      "rateRuleStrategyList": [
        {
          "feeRate": "<协议支付费率>",
          "minFee": "<最低手续费>"
        }
      ]
    },
    {
      "productId": "421",
      "productModelId": "10370560005",
      "feeAcctId": "1",
      "billModel": "1",
      "beginEffectiveTime": "<生效时间>",
      "rateRuleStrategyList": [
        {
          "feeRate": "0",
          "minFee": "0",
          "maxFee": "0"
        }
      ]
    }
  ],
  "prodExtendInfo": {
    "openSupplyInfo": {
      "shareProdRatio": 100,
      "supplyFiles": [
        {
          "fileType": "9915999",
          "fileUuid": "<产品开通附件UUID>"
        }
      ]
    }
  }
}
```

说明：如果资料 2 至 6 已在会员创建、会员信息修改或补充材料阶段上传，且产品侧确认无需重复上传，则 `supplyFiles` 可不重复传。样例保留 `9915999` 是为了强调需要补充产品开通附件时的文件类型选择。

### 5.4 成功响应结构

产品开通接口成功响应示例：

```json
{
  "success": true,
  "result": {
    "openState": "1",
    "openApplyNo": "<产品开通申请号>"
  }
}
```

其中 `openState=1` 表示本次产品开通申请已受理或成功返回，最终状态仍应以产品侧状态定义、回调或查询结果为准。

## 6. 421 补充资料上传规则

### 6.1 是否需要在产品开通时补充上传

| 场景 | 产品开通时是否需要补充上传 | 处理方式 |
|---|---|---|
| 开户或会员创建/修改时已经送过资料 2 至 6 | 通常不需要重复上传 | 保留原上传记录和文件 UUID，按产品侧要求确认是否复用。 |
| 未送过资料 2 至 6，且要开分账类产品 | 需要上传 | 按销售要求准备资料 2 至 6，并在产品开通补充附件中选择 `9915999`。 |
| 未送过资料 2 至 6，但不开分账类产品 | 通常不需要产品开通补充材料 | 仍需按开户和合规准入要求处理基础资料。 |

### 6.2 产品开通补充附件类型

| 文件类型 | 名称 | 条件 |
|---|---|---|
| `9915999` | 产品开通附件 | 本次分账类产品补充材料重点选择该类型。 |
| `9999914` | 经营场所照片 | 经营场景选择线下时必填。 |
| `9999921` | APP 页面截图 | 经营场景选择 APP 时必填。 |
| `9999932` | 网站授权函 | 经营场景选择网页端且运营方非本企业时，除网站域名地址外，还需网站管理委托书及运营方营业执照或联合运营说明函。 |
| `9999942` | 小程序联合运营说明函 | 经营场景选择移动端-小程序且运营方非本企业时，需联合运营方业务场景说明函或联合运营说明函。 |
| `9999972` | 快应用联合运营说明函 | 经营场景选择移动端-快应用且运营方非本企业时，需联合运营方业务场景说明函或联合运营说明函。 |

注意：本次开分账类产品时，销售口径中的资料 2 至 6 如果要随产品开通补传，优先按产品开通附件 `9915999` 处理，不要误把它当成银行类型或技术支持字段问题。

## 7. 第三步：交易验证与结算说明

### 7.1 代运营商户绑卡扣款

代运营商户完成开户和 `144 + 421` 一次性产品开通后，需要按协议支付文档完成绑卡扣款验证。

验证要点：

1. 绑卡扣款使用代运营商户对应的商户号、终端号和协议支付参数。
2. 扣款请求需要配置交易结果通知地址。
3. 同步返回不能单独作为最终成功依据，应结合支付结果通知和支付订单查询确认最终状态。
4. 通知处理完成后，接入方通知地址应按接口规范返回成功标识，避免重复通知导致重复处理。

### 7.2 从代运营商户分账到分账接收方商户

分账交易使用余额分账接口，从代运营商户分账到分账接收方商户。余额分账文档中的网关接口路径为 `/v1/split/balanceSplit`。

判断要点：

1. `txn_state=SUCCESS` 表示本次分账交易成功。
2. `share_no` 是宝付生成的分账单号，后续查询和排查需要保留。
3. 分账明细中的 `detail_no` 是每个接收方对应的分账明细单号。
4. 分账金额合计应等于交易分账总金额。

### 7.3 分账通知和查询

接入要求：

1. `notify_url` 必须是接入方可公网访问并能稳定接收通知的地址。
2. 接收通知后需要按接口规范返回成功标识，避免宝付重复通知。
3. 以第一次收到的成功通知为准，避免重复入账、重复记账或重复触发后续业务。
4. 当同步响应、异步通知或本地状态不一致时，使用分账查询接口按 `trans_id`、`share_no` 等关键字段核对最终状态。

### 7.4 分账接收方自动结算

当前展示口径需要提前告知客户：

1. 分账接收方结算目前可能显示为“代理转账入金”。
2. 如果代运营商户和分账接收方都已完成畅联入网，分账接收方看到的银行流水可能表现为由畅联打一笔款。
3. 后续展示口径可能优化为“分账商户转账”或按配置主体转账。
4. 客户验收时，不要仅凭银行流水付款方名称判断分账链路是否异常，应结合分账单号、分账明细、通知和查询结果共同核对。

| 检查项 | 验收标准 |
|---|---|
| 代运营开户 | 返回 `uid`，且商户属性为代运营成员商户。 |
| 144 + 421 一次性产品开通 | 同一次产品开通请求中包含 `144` 和 `421` 两个 `feeRuleList` 条目。 |
| 144 产品参数 | `productId=144`，`productModelId=10370560005`。 |
| 421 产品参数 | `productId=421`，`productModelId=10370560005`。 |
| 421 扩展信息 | 不再要求固定传 `bankType`、技术支持电话或 `techSupportFlag`；分账比例和补充附件按产品条件传。 |

| 分账接收方进件 | 对私/对公接收方按对应接口进件成功。 |

## 9. 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 未按一次性产品开通口径说明 `144 + 421` | 客户理解和接入实现可能偏离本次交付方案。 | 对客户表达为 `144 + 421` 一次性产品开通，同一次请求内传两个 `feeRuleList` 条目。 |
| 把 144 或 421 的 `productModelId` 填成其他货架 | 产品可能未按本次交付方案生效。 | 144 和 421 均使用 `10370560005`。 |
| 继续要求 421 固定传 `bankType=HT` | 接入方会围绕无效字段反复确认。 | 当前口径为不需要传银行类型。 |
| 要求客户提供技术支持电话 | 增加无必要资料收集，并可能引发字段用途争议。 | 当前口径为不需要传技术支持电话或 `techSupportFlag`。 |
| 需要补充资料时未选择 `9915999` | 产品开通附件类型不匹配，可能导致审核退回。 | 分账类产品补充材料按产品开通附件 `9915999` 传。 |
| 已在开户或会员补充资料阶段送过资料 2 至 6，又在产品开通重复上传 | 接入负担增加，资料口径容易冲突。 | 先确认历史资料是否已送过，已送过则不重复上传，除非产品侧要求。 |
| 用父级代理商 UID 开产品或发起交易 | 产品或交易可能落到错误主体。 | 使用代运营开户返回的商户 `uid`，交易侧使用代运营商户对应的 `member_id`、`terminal_id`。 |
| 只做分账接收方进件，不做绑定关系 | 分账发起时无有效接收关系。 | 进件后确认或单独调用绑定接口。 |
| 分账只看同步响应，不处理通知和查询 | 本地状态可能与宝付最终状态不一致。 | 同步响应、异步通知、分账查询一起作为验收和排障依据。 |
