## 一句话定位

验证页不是定义页，而是证据页。它要让读者知道这套方法解决了哪些真实问题，也知道哪些能力仍然只是候选。

## 这页适合谁看

| 如果你现在要判断 | 先看这里的什么 | 看完能得到什么 |
|---|---|---|
| 这套方法是不是概念化 | 当前证据总览 | 知道哪些环节已经被实际使用 |
| 对外材料为什么要有质量检查 | 失败样例 | 知道没有检查会怎样漂移 |
| AI 规则写了是否就生效 | 行为验证案例 | 知道规则需要验证记录和证据 |
| 哪些不能夸大 | 边界表 | 知道现在还没证明什么 |

## 当前证据总览

| 能力 | 当前证据 | 证明了什么 |
|---|---|---|
| 文章学习 | 外部文章先评分、再精读、再判断是否吸收 | 学习不是摘要，而是有门槛的能力吸收 |
| 对外材料质量检查 | 失败稿被冻结，评分结论被撤销，检查规则被加硬 | 对外材料不能先发后补证据 |
| 行为规则验证 | 链接触发、能力卡触发、质量复核都保留验证记录 | 规则不是写下就算生效 |
| 飞书同步 | 更新后需要 read-back 验证标题、开头和 log id | 同步成功不能只凭口头记忆 |
| 候选经验治理 | 项目经验先作为候选，不直接进入团队共识 | 防止一次性经验污染团队规则 |

## 失败样例

| 失败 | 发生了什么 | 修正后的判断 |
|---|---|---|
| 参考结构未读全 | 只看入口页，没有先读阅读地图里的真实文章 | 参考结构检查必须失败 |
| 缺图被降级 | 参考页有关键视觉，本地稿没有对应视觉 | Visual Gate 必须失败 |
| 硬性检查失败仍打分 | 参考结构检查失败后仍出现 92 分 | 评分必须作废 |
| 五篇合成一篇 | 把入口页和子页打包成一个审核稿 | 不算完成 split |

## 不能过度承诺什么

| 不能说 | 更准确的说法 |
|---|---|
| 有知识库就自动形成团队共识 | 知识库提供证据、结构和复用路径，共识仍需要验证 |
| 有目录就能被 AI 正确理解 | 目录只能帮助定位，语义理解还要靠上下文和规则 |
| 飞书同步成功就是发布完成 | 还需要质量检查、回读验证和发布状态确认 |
| 一次流程跑通就适用所有项目 | 只能说明当前场景通过，跨项目仍要积累证据 |

## 下一阶段验证

后续证据应该来自真实使用：一份新材料能否顺利进入系统；一次汇报能否复用已有结构；一个重复问题能否找到历史判断；一个团队经验能否从候选池稳定晋升。
