# AICoding L1-L4 路线图

## 一句话结论

我们现在已经基本走到 `L2`，下一步不是继续堆工具，而是把 `L2 -> L3` 的阶段协作固定下来，再用更硬的 gate 和透视能力往 `L4` 推。

## 这页适合谁看

| 如果你现在想解决 | 先看什么 |
|---|---|
| 我们现在到底处在哪个阶段 | `L1-L4` 定义 |
| 下一步该先补哪一层能力 | 路线图和推进顺序 |
| 为什么不是先做更多自动化 | 阶段门槛与依赖关系 |

## L1-L4 定义

| Level | 核心目标 | 人机关系 | 代表能力 | 典型风险 |
|---|---|---|---|---|
| `L1` | AI 辅助查阅和局部执行 | 人主导，AI 做局部补全和查询 | 文档生成、局部改写、命令执行、基础检索 | 回答快，但没有稳定边界 |
| `L2` | AI 按约束完成单次任务 | 人定目标与边界，AI 能按 gate 执行 | `AGENTS.md`、rules、skills、OpenSpec、Lore、Graphify 联动 | 能做事，但阶段协作还不够稳定 |
| `L3` | AI 进入可验证的阶段化协作 | 人定义阶段目标，AI 在需求/设计/研发/CR/验收中扮演固定角色 | 脑暴、SDD、前置 CR、`TDD inside OpenSpec`、持续吸收 | 如果阶段契约不清，容易回退成 L2 |
| `L4` | AI 驱动的工程协作面 | 人负责方向和例外处理，AI 负责大部分日常推进与知识沉淀 | 自动路由、自动 lint、阶段指标、功能透视、知识持续吸收 | 如果没有硬 gate，会产生“自动化幻觉” |

## 当前判断

| 维度 | 当前状态 | 结论 |
|---|---|---|
| 约束层 | `AGENTS.md`、rules、skills 已成型 | 已具备 `L2` 基础 |
| 过程层 | OpenSpec proposal / design / tasks + evals 已联动 | `L2` 稳定 |
| 知识层 | Lore + Graphify 分工已明确 | `L2` 稳定 |
| 验证层 | TDD、routing、benchmark、readback 已进入常规流程 | 正在逼近 `L3` |
| 阶段协作 | 需求/设计/研发/CR/验收 还没完全固定成统一协议 | `L3` 尚未完成 |

## 为什么说我们现在是 L2，而不是 L3

| 已经有 | 还缺什么 |
|---|---|
| AI 会按 gate 走，不再完全自由发挥 | 需求、设计、研发、CR、验收还没有统一阶段模板 |
| OpenSpec + TDD 已经合流 | 还没有把每个阶段的入场条件和完成条件固定下来 |
| Lore / Graphify / git truth 已能支撑单次任务 | 还没有形成长期稳定的项目透视面板 |
| Feishu 同步和 readback 已纳入工作周期 | 还没有形成全面自动 lint / CI gate |

## 为什么不是直接冲 L4

| 如果直接跳 L4 | 结果 |
|---|---|
| 先做大量自动路由和自动化脚本 | 会把阶段不清的问题自动化，放大噪声 |
| 先做功能透视和知识自动沉淀 | 会得到很多产物，但阶段契约仍然松散 |
| 先做“AI 自主协作” | 容易绕开人定义的边界和验收 |

更稳的顺序是：

1. 先固定 `L2 -> L3` 的阶段协作。
2. 再把阶段 gate 做硬。
3. 再做透视、面板和自动化。

## 从 L2 走到 L3 的关键能力

| 能力 | 现在有多少 | 下一步怎么补 |
|---|---|---|
| 需求脑暴 | 部分有 | 固定 brainstorm 模板和输出格式 |
| `SDD first` | 已起步 | 固定设计页结构、接口边界和风险表 |
| 前置 CR | 已有 reviewer 资产 | 固定进入 CR 前的自检与 reviewer pass |
| `TDD inside OpenSpec` | 已起步 | 把 failing case / GREEN criteria / evidence 常态化 |
| 持续吸收 | Lore 已成型 | 固定从 logs/review 到 durable memory 的节奏 |

## 从 L3 走到 L4 的关键能力

| 能力 | 作用 |
|---|---|
| query 分类自动化 | 让 Lore / Graphify / OpenSpec 路由更稳定 |
| git / Graphify / OpenSpec / Lore 联合透视 | 建立功能地图、改动热点、模块健康度视图 |
| 更硬的 CI / pre-push gate | 把“建议”升级成“硬边界” |
| 发布后 lint | 自动检查图文、标题、readback、同步一致性 |
| 知识自动草案 | 把 logs / benchmark / review 结果自动转成 Lore 草稿 |

## 推荐推进顺序

| 优先级 | 先做什么 | 原因 |
|---|---|---|
| `P1` | 固定 `需求 -> 设计 -> 研发 -> CR -> 验收 -> 沉淀` 的阶段协议 | 这是 `L3` 的最低门槛 |
| `P2` | 把前置 CR 和验收 gate 再加硬 | 返工主要发生在这里 |
| `P3` | 做 git / Graphify / OpenSpec / Lore 联合透视 | 为功能地图和知识面板提供数据基础 |
| `P4` | 再往 `L4` 的自动化协作层推进 | 避免在阶段协议未稳时过早自动化 |

## 一句话收束

我们的路线不是“让 AI 更像人”，而是“让 AI 更像一个有边界、有阶段、有验证的工程协作面”。
