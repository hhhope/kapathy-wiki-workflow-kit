## 2.0 现状

### 主账户与资金链路

- **F-008 / confirmed**：顶部主体为“宝财通 2.0 收单商户号”。
- **F-009 / confirmed**：收单商户号下挂“二级户 a”和“二级户 b”。
- **F-010 / confirmed**：二级户 a 可升级为“收单商户 A”。
- **F-011 / confirmed**：二级户 b 可升级为“分账接收方 B”。
- **F-012 / confirmed**：100 元收单资金从“未结算”进入收单商户 A 对应的基本户语义路径。
- **F-013 / confirmed**：收单商户 A 发起分账，资金进入分账接收方 B。
- **F-014 / confirmed**：二级户 b 可提现至绑定卡；分账接收方 B 可提现至结算卡。

### 模式说明

- **F-015 / transcribed**：2.0 方案主线为去电子户，并将二级户升级为待约商户/收单商户或分账接收方。
- **F-016 / transcribed**：平台收单/代付商户线下开 UUID；二级户升级与交易需要该标识。
- **F-017 / transcribed**：二级户升级为分账接收方时需要材料补查、关系绑定和产品/协议配置。

## 3.0 目标

### 主账户与资金链路

- **F-018 / confirmed**：顶部主体改为“宝财通 3.0 代付商户号”。
- **F-019 / confirmed**：代付商户号下仍展示二级户 a 和二级户 b，并分别升级为收单商户 A、分账接收方 B。
- **F-020 / confirmed**：收单、分账、绑定卡提现、结算卡提现的核心展示路径与 2.0 使用同一比较语法。
- **F-021 / transcribed**：3.0 收单接口仍传二级户，并依据交易商户是否为升级待约商户进入对应收单和分账处理。

### 推荐方向边界

- **F-022 / confirmed**：本次 H5 以 3.0 作为推荐方向、2.0 作为对照；这是用户确认的评审主线，不代表业务收益已验证。
- **F-023 / transcribed**：截图还保留“电子户 + 平台（老收单商户号）”等过渡/备选模式，其具体适用范围不作为默认推荐结论。

## 业务规则

### 收单

- **F-024 / transcribed**：交易商户号需要判断是否属于升级待约商户；新订单进入平台收单或待分账处理。

### 分账

- **F-025 / transcribed**：新分账逻辑需识别原支付订单，并定位分账接收方的未结算资金或待分账关系。
- **F-026 / transcribed**：支持按代理商维度配置自动解冻周期；不同分账关系不应串扰。

### 退款

- **F-027 / transcribed**：分账前退款优先从收单商户/待分账资金路径处理；分账后退款涉及分账接收方或兼容旧路径。

### 提现

- **F-028 / confirmed**：二级户/升级商户和分账接收方存在不同提现出口，分别对应绑定卡或结算卡。

### 余额、收支与对账

- **F-029 / transcribed**：需要支持待升级商户号或分账接收方的余额、收支与交易订单查询。
- **F-030 / transcribed**：余额调账需区分已分账资金与未分账资金，并校验可用余额与电子户/二级户余额边界。

## 改造项

1. **F-031 / transcribed — 宝财通开户**：新增二级升待约商户菜单和按钮，支持 Excel 导入商户信息；新增产品开通与状态记录，保留批次、商户、开通状态、创建/更新时间等审计信息。
2. **F-032 / transcribed — 材料补查**：二级户窗口返回材料补查 H5 链接，通过证件 OCR 与平台信息完成材料补齐。
3. **F-033 / transcribed — 开户 H5**：由二级户窗口打开开户 H5；非必填字段可通过证件 OCR 和平台商户信息补齐。
4. **F-034 / transcribed — 升待约接口简化**：减少商户重复传值，复用 OCR/平台信息；具体字段边界待接口原文确认。
5. **F-035 / transcribed — 分账商户关系批量绑定**：新增批量记录、批量绑定和导出能力；记录批次号、分账方、被分账方、状态、创建人/时间、更新时间。
6. **F-036 / transcribed — 平台模式切换**：配置平台收单商户号、平台代付商户号、模式和是否切换到新模式。
7. **F-037 / transcribed — 余额调账**：新增余额转账入口，支持已分账资金与未分账资金的受约束划转。

## 风险与待确认

- **F-038 / needs_confirmation / 产品**：历史订单在旧模式与新模式之间是否可以继续分账，边界和切换时点待确认。
- **F-039 / needs_confirmation / 产品**：已分账和未分账资金能否跨商户主体划转，合规依据待确认。
- **F-040 / needs_confirmation / 研发**：退款究竟从收单商户基本户、待分账余额还是分账接收方出款，需按订单状态确定权威规则。
- **F-041 / needs_confirmation / 研发**：二级户 a/b、升级商户号、UUID、产品开通状态之间的唯一映射和幂等规则待接口文档确认。
- **F-042 / needs_confirmation / 测试/合规**：电子户余额、二级户在途户、平台主体待分账账户之间的余额校验公式待确认。
- **F-043 / needs_confirmation / 测试/合规**：截图中的“04 流程”、协议号、ACS 账户及部分调账字段字号过小，必须以原始需求/接口文档复核。
- **F-044 / needs_confirmation / 产品**：保留电子户方案、去电子户 2.0 方案和 3.0 方案是否需要并行兼容，以及各自适用商户范围待确认。
