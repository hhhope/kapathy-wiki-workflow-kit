# Agent-Task 协作流程 Skill

**格式与模板**：生成 role-task、collaboration-flow、confirm-and-edit、progress 四类文档时，**必须先阅读 [reference.md](reference.md)**，按其中模板与格式输出，避免结构或时间格式不一致。

## 触发场景

- 用户要求建立「协作流程」「Role & Task」「进度跟踪」「需我确认再执行」
- 用户要求产出按「分支+作者」归档到 agent-task
- 用户说「先跟我确认协作流程」「目标/产出要可跟踪」

---

## 协作问题回顾（为何这样约定）

以下来自实际协作中的问题，已沉淀为上述约定：

| 问题 | 后果 | 约定 |
|------|------|------|
| 增加/修改目标后未即时同步 role-task、confirm-and-edit、progress | 下一轮仍按旧目标执行或任务列表与目标不一致 | **目标变更当轮**必须同步三处文档与产出物索引（见第四节） |
| 时间只写日期不写时分秒 | 无法判断「最后更新」是否足够新，中断恢复时难以追溯 | 所有时间**精确到 YYYY-MM-DD HH:mm:ss**（见第一、三、六节） |
| 进度更新间隔过长或只在「全部做完」才更新 | 中断后不知停在哪一步，恢复成本高 | **每子步骤结束**或**约 1 分钟**更新 progress（见第三节） |
| 目标改为「不新增模块」后，产出物索引或 confirm 选项仍写旧模块路径 | 文档与实现不符，后续参考出错 | 目标/范围变更时**产出物索引与 confirm 受影响的项一并修订**（见第四节） |
| 分支/作者变更后未改产出目录或文档内引用 | 产出散落或路径错误 | **分支/作者变更**则目录与全文引用同步替换（见第五节） |
| 包名/目录修正后只改代码未记入文档 | 审计与恢复时不知道曾做过修正 | **包/目录修正**须在 progress 或 role-task 记录修正内容、原因、时间（见第五节） |
| role-task 任务列表与 progress 未完成/已完成不一致 | 状态分裂，恢复时不知道以谁为准 | **多文档一致**：任务 ID、描述、状态两处同时更新（见第三、五节） |
| 执行分支/包名等时未读 confirm-and-edit | 用了旧分支名或旧包名，与用户确认不一致 | **执行前**读取 confirm-and-edit 对应项再执行（见第二、五节） |

## 一、产出物位置约定（必须遵守）

**约束：agent-task 与项目放在一起**。agent-task 必须位于**当前工作区/项目根目录**下，与项目代码同仓存放、一并纳入版本管理（如 git）；禁止放在用户主目录、系统临时目录或项目外路径。所有路径均**相对于当前项目根**。

| 类型 | 路径规则 |
|------|----------|
| 根目录 | `{项目根}/agent-task/`，即项目根下的 `agent-task/` |
| 按分支+作者 | `agent-task/{分支名}/{作者}/`，分支名中 `/` 改为 `-`，如 `component-2025-03-09-exception/peng_yan/` |
| Role & Task | 上述目录下 `YYYY-MM-DD-role-task.md` |
| 协作流程 | 上述目录下 `YYYY-MM-DD-collaboration-flow.md` |
| 需确认/可修改 | 上述目录下 `YYYY-MM-DD-confirm-and-edit.md` |
| 进度跟踪 | 上述目录下 `YYYY-MM-DD-progress.md` |

所有时间相关字段**必须精确到时分秒**，格式：`YYYY-MM-DD HH:mm:ss`（如 `2025-03-09 14:32:05`）。

---

## 二、协作流程（Agent 执行顺序）

1. **首次**：在 `agent-task/{分支}/{作者}/` 下创建上述 4 个带日期的 md，并请用户确认协作流程与 confirm-and-edit。
2. **执行中**：严格按 role-task 的任务列表执行；关键决策（分支名、包名、模块名、表名等）以 confirm-and-edit 为准，执行前必须读取对应项。
3. **进度**：在**每个可交付子步骤结束**或**约每 1 分钟**（以先到为准）更新 progress.md（见下）。
4. **中断恢复**：用户提供 progress 中「当前正在做的任务」+「未完成任务」即可继续；新会话先读当日 role-task、progress、confirm-and-edit 再执行。

---

## 三、进度更新规范（防止中断、便于追溯）

- **最后更新**：每次更新 progress 时写入当前时间，格式 `YYYY-MM-DD HH:mm:ss`。
- **完成时间**：每项「已完成任务」的完成时间也使用 `YYYY-MM-DD HH:mm:ss`。
- **更新时机**：至少在下述任一时刻更新 progress：
  - 完成一个可交付子步骤（如一个模块、一组文件、一次可测试单元）；
  - 开始新任务（把「当前正在做的任务」改为新任务）；
  - 超过约 1 分钟未更新时，补一次「当前正在做的任务」+「最后更新」。
- **三表一致**：progress 的「当前任务」「未完成」「已完成」须与 role-task 中的任务 ID/描述对齐；任一处任务状态变更时，同步更新另一处。

---

## 四、目标或范围变更时的即时同步（必须执行）

一旦用户**增加目标**或**修改目标**（例如「不新增模块，全部在 XX 内实现」「目录改到 XX 下」），**当轮对话内**必须完成：

| 同步项 | 动作 |
|--------|------|
| **role-task.md** | 更新「目标与范围」、更新「任务列表」中受影响的任务描述与依赖，使任务列表与最终目标一致。 |
| **confirm-and-edit.md** | 更新与目标相关的条款（如模块位置、包名、首期实现范围）；若某选项因目标变更已失效，改为新选项或标注「已由目标变更覆盖」。 |
| **progress.md** | 更新「当前正在做的任务」「未完成任务」列表（增删/改任务 ID 与描述）；若已有任务被取消或合并，在「已完成」或「未完成」中相应调整；**最后更新**写入当前时间（到时分秒）。 |
| **产出物索引** | 若目标变更导致路径、包名、模块名变化，在 role-task 的「产出物索引」或 progress 的说明中同步修改，并注明修正原因与时间（到时分秒）。 |

禁止在目标变更后仍按旧目标执行或只更新部分文件。

---

## 五、其他必须遵守的约定

- **agent-task 与项目同仓**：创建或引用 agent-task 时，路径必须基于**当前项目根**（Workspace Root），不得使用项目外的绝对路径；确保 agent-task 可随项目一起提交、拉取与归档。
- **分支/作者变更**：若用户修改「提交分支」或「作者」，则产出目录改为项目根下 `agent-task/{新分支名}/{新作者}/`，并将所有已生成文档移动或复制到新目录，且全文中的分支名、作者、路径引用替换为新值。
- **包/目录修正**：若用户要求「目录修正到 XX 下」「包名改为 XX」，除代码与配置迁移外，须在 progress 或 role-task 中**记录修正**：修正内容、原因、时间（到时分秒）；产出物索引中的路径/包名同步修改。
- **执行前读 confirm**：凡涉及分支名、包名、模块名、表名、首期范围的执行动作，执行前必须读取 confirm-and-edit.md 中对应项，按用户最终填写内容执行。
- **多文档一致**：role-task 的任务列表与 progress 的未完成/已完成列表必须一一对应；任务 ID、描述、状态变更后两处同时更新。

## 六、progress.md 模板要点

```markdown
**最后更新**: YYYY-MM-DD HH:mm:ss

## 当前正在做的任务
- **T?**：具体描述。

## 未完成任务
| ID | 任务 | 状态 |

## 已完成任务
| ID | 任务 | 完成时间 |
（完成时间格式：YYYY-MM-DD HH:mm:ss）
```

## 七、检查清单（目标变更或大步骤后自检）

- [ ] **agent-task 位于当前项目根下**，路径为项目内相对路径，未使用项目外目录
- [ ] role-task 的「目标与范围」「任务列表」与用户最新目标一致
- [ ] confirm-and-edit 中受目标影响的选项已更新或标注
- [ ] progress 的「当前任务」「未完成」「已完成」与 role-task 任务列表一致
- [ ] 所有时间字段已使用 YYYY-MM-DD HH:mm:ss
- [ ] 产出物索引中的路径/包名与当前实现一致
- [ ] 分支名、作者、产出目录在文档中统一
