我发现 Anthropic 真正厉害的不是 Claude Code

基于现有 Anthropic 调研稿重写，新增事实校验和数据支撑，正文中文主写，专名保留原名。

我发现 Anthropic 真正厉害的不是 Claude Code

事情是这样的。

前几天我一直在看 Anthropic 这家公司，看 Claude Code，看 Claude Cowork，看 OpenAI 的那篇智能体工程文章，看字节 Seed 的团队方向。

看着看着，我突然意识到一件事。

我们之前很容易把 Claude Code 看成一个写代码工具。

就是那种，你给它一个需求，它帮你改文件，跑测试，提交代码。程序员效率提升，项目交付变快，老板很开心，工程师有点慌。

这个理解不能说错。

但太浅了。

浅到有点浪费这个材料。

我觉得 Claude Code 真正值得研究的地方，不是它会不会写代码，也不是它到底比 Cursor 强多少，更不是它能不能让产品经理自己搓一个小工具出来。

真正值得看的是，Anthropic 这家公司，正在通过 Claude Code 这个项目，试着回答一个更大的问题。

一个强模型，怎么进入真实工作环境？

它怎么读文件，怎么调用工具，怎么改东西，怎么跑验证，怎么被人类拦住，怎么留下痕迹，怎么在下一次任务里记住上一次踩过的坑。

这才是 Claude Code 的主线。

不是写代码。

是行动。

这一下就把事情从工具层，推到了公司运营层。

我先把几个硬事实摆在这里，免得后面聊嗨了飘。

2025 年 2 月 24 日，Anthropic 发布 Claude 3.7 Sonnet，同时把 Claude Code 作为一个有限研究预览放出来。官方当时的说法是，这是一个命令行里的智能体编程工具，能让开发者把相当一部分工程任务直接交给 Claude。

到 2025 年 5 月 22 日，Claude 4 发布，Claude Code 从研究预览进入正式可用。一起出来的还有编辑器集成，代码托管平台里的后台任务，以及 Claude Code 开发套件。

你看，这里已经不是「帮我补一行代码」的叙事了。

它从一开始就是奔着工作环境去的。

更骚的是，Anthropic 自己产品页上给了几组非常重的数据。

Stripe 把 Claude Code 部署给了 1370 名工程师，其中一个团队用 4 天完成了 1 万行 Scala 到 Java 的迁移，而他们原本估算这要 10 个工程师周。

Ramp 把 Claude Code 接进研发流程后，事故调查时间降低了 80%。而且不只是工程团队，销售、风险、财务这些非工程团队，也开始用自然语言查数仓，不再自己写结构化查询语句。

Wiz 把一个 5 万行的 Python 库迁到 Go，大概用了 20 个小时的主动开发时间。原来的人工估算是 2 到 3 个月。

Rakuten 的新功能平均交付时间，从 24 个工作日降到 5 个工作日。

这些数字很夸张。

但我反而觉得，数字本身不是最重要的。

真正重要的是，这些数字都指向同一件事，Claude Code 不是在帮人快一点敲代码，它在把原本需要人穿越很多系统才能完成的工作，压成一个可委托的任务。

你给目标。

它进环境。

它找上下文。

它改东西。

它跑验证。

你来判断能不能交付。

这才是变化。

说到这里，我想起李想和罗永浩那段访谈。

李想讲 人工智能公司组织架构的时候，说得特别有意思。他不是按传统的研发、产品、销售、运营去看，而是按一个人的器官去看。

心脏是算力和数据，大脑是基座模型，手脚是软件和智能体，身体是硬件，评测系统像裁判或者免疫系统。

坦率的讲，这个比喻第一次听会有点玄。

但拿它看 Anthropic，突然就顺了。

Claude 是大脑。

Claude Code 是手脚。

Claude Cowork 是手脚从研发现场，伸向普通知识工作现场。

权限、人工确认、测试、评测、安全策略，是免疫系统。

CLAUDE.md、记忆、设置、子智能体、钩子机制，是神经系统。

我说这些词的时候，已经尽量用中文了。因为如果全写成 记忆、设置、子智能体、钩子机制、智能体安全，就会变成一种很烦人的技术英语堆叠。看着很专业，其实不一定更清楚。

用人话讲就是，Anthropic 不是只在做一个更会写代码的 Claude。

它是在给 Claude 补器官。

先有脑子，再有手脚，再有记忆，再有边界，再有自我检查，再有一套能让它进公司干活的神经系统。

这个判断有一个很强的证据，就是 Anthropic 自己内部怎么用 Claude Code。

2025 年 7 月 24 日，Anthropic 发了一篇文章，专门写自己公司里不同团队怎么用 Claude Code。

里面最有意思的地方，不是工程师用它写测试和修 bug。

这太正常了。

真正有意思的是，法律团队用它做内部电话树原型，市场团队用它生成广告变体，数据科学家用它看数据管道，设计团队用它写测试和自动化评论。

市场团队那个例子尤其直观。

他们做了一个流程，处理包含几百条广告的表格，找出表现差的广告，再生成新变体。还做了一个 设计工具插件，可以识别画板，通过替换标题和描述，最多生成 100 个广告版本，把原来几个小时的复制粘贴，压成半秒一个批次。

半秒。

这个数字很小，但很有冲击力。

因为它打掉的不是写代码时间，而是组织里最常见、最让人疲惫的那种低价值摩擦。

复制。

粘贴。

改标题。

对格式。

再复制。

再粘贴。

很多公司里真正吞掉人的，不是一个惊天动地的大项目，而是这些看起来一点都不高级的小动作。

它们像灰尘一样落在每个人身上。

你不觉得它们重要，但它们每天都在消耗你的注意力。

Claude Code 被 Anthropic 内部非工程团队拿去用，说明一件事，代码只是入口，真正被打开的是「把想法变成可执行物」的能力。

过去一个市场同学想做广告自动化，要找产品排期，找工程评估，写需求，开会，等开发，再测，再改。

现在他可能先自己做一个粗糙但能跑的东西。

不是最终生产系统。

但至少是一个能被看见，能被讨论，能被验证的东西。

这就是组织边界开始变化的地方。

注意，我不是说人人都要变成程序员。

这句话太廉价了。

也不对。

法律同学不会因为能做一个电话树原型，就突然变成后端工程师。市场同学不会因为能生成 100 个广告版本，就突然接管生产系统。设计同学不会因为能写一点测试，就变成测试负责人。

专业责任没有消失。

只是专业人员离可执行物更近了。

以前很多工作是这样的，一个人脑子里有想法，写成文档，另一个人读文档，翻译成设计，再有人把设计翻译成代码，再有人把代码翻译成测试，再有人把测试结果翻译成上线判断。

一层一层翻译。

每翻译一次，信息都丢一点，责任也模糊一点。

Claude Code 这类东西出现之后，一部分翻译链条会被压缩。人还是要负责判断，但判断对象不再只是文档，而是一个能跑的东西。

这件事听着简单，其实很大。

因为公司协作里最贵的东西，从来不只是人力，而是上下文在组织里来回搬运的成本。

OpenAI 其实也在讲同一件事。

他们那篇智能体工程文章里有个非常关键的说法，给 Codex 的不是一本 1000 页的说明书，而是一张地图。

他们试过把所有规则塞进一个巨大的 智能体说明文件，结果失败得很符合直觉。上下文不够用，规则太多等于没规则，文档会过期，也很难验证。

所以他们把仓库里的知识变成结构化文档，计划，测试，质量记录，让智能体从一个短入口开始，知道该去哪里找东西。

这和 Anthropic 的路径对得上。

一个是 Claude Code，一个是 Codex。

一个从产品和内部团队讲，一个从工程仓库讲。

但底层共识一样，强模型要干活，不能只靠对话框，得有环境，有地图，有工具，有验证，有边界。

字节 Seed 也能做一个旁证。

Seed 官网公开列出的团队方向，有大语言模型，基础设施，视觉，语音，多模态交互和世界模型，科学智能，机器人，负责任人工智能。

我不敢说这就是字节内部真实组织图。

这点必须谨慎。

但至少从公开能力版图看，头部 人工智能公司越来越不是按传统部门叙事，而是在按能力器官叙事。

大脑，感官，基础设施，身体，安全。

回到 Anthropic。

如果只到 Claude Code，这个故事还停在研发现场。

真正让我觉得有意思的，是 Claude Cowork。

Anthropic 在 Claude Cowork 产品页里说得很直白，普通聊天在很多时候有用，但不总是对的工具。Anthropic 内部的市场和数据团队，开始绕过 Claude 的聊天界面，去用 Claude Code，因为它能处理复杂的多步骤工作，比如建工具，挖数据。

于是 Claude Cowork 出现了。

它的定位不是让你写代码，而是你给一个目标，它在你的电脑、本地文件和应用里工作，最后交付一个完成品。

这段话我看了好几遍。

因为这里的关键词已经不是代码了。

是电脑。

是本地文件。

是应用。

是交付物。

这说明 Claude Code 不是终点，它是原型。

研发现场只是第一个训练场，因为代码场景太适合训练行动能力了。文件可读，命令可跑，测试可验证，版本可回滚，错误可复现。

等这套能力跑通，它自然会往外扩。

扩到文件夹。

扩到表格。

扩到邮件。

扩到合同。

扩到一切可以被读取、整理、修改、验证的知识工作对象。

这个时候你再看 Anthropic 的安全叙事，就不会觉得它只是品牌包装。

当模型只是回答问题的时候，安全主要是输出安全。

当模型能改文件、跑命令、动应用、查数据的时候，安全就变成行动安全。

它能看什么？

它能改什么？

它什么时候必须停下来问人？

它干错了以后，怎么复盘？

谁承担最后的责任？

这些问题不解决，所谓智能体进公司，就是一句很危险的口号。

Anthropic 的负责任扩展政策，到 2026 年第三版的时候，已经开始讲更具体的东西，比如风险报告每 3 到 6 个月发布一次，在某些情况下引入外部评审，建立关键人工智能开发活动的集中记录，用人工智能分析这些记录里的安全威胁和异常行为。

你看，它讲的不是「我们很安全」这种空话。

它在讲记录，评审，路线图，公开目标，外部审查。

这些东西听起来不性感。

但它们是强模型行动化之后真正需要的东西。

说真的，我有时候觉得，今天很多人讨论智能体，最大的问题是只看到了兴奋的那一半。

让它帮我做事。

让它帮我写代码。

让它帮我跑流程。

让它帮我自动完成。

听起来太爽了。

但另一半是什么？

是它凭什么能做。

它在哪里做。

它做错了谁知道。

它越权了谁拦住。

它做完了谁判断。

没有这一半，智能体就是一个很会动的黑箱。

而 Anthropic 真正让我觉得值得研究的地方，恰恰是它没有只讲「动起来」。

它一直在讲，怎么让这个东西被控制。

这也是我觉得 Claude Code 和 Claude Cowork 重要的原因。

它们不是两个孤立产品，而是一条非常清楚的路线。

Claude 是大脑。

Claude Code 是大脑第一次比较系统地接上手脚，进入研发现场。

Claude Cowork 是这双手脚开始离开代码库，走向普通知识工作。

权限、记忆、测试、评审、安全政策，是它一路长出来的神经系统和免疫系统。

这套东西如果继续演进下去，未来公司的变化可能不是每个人旁边多一个聊天助手。

而是每一类工作，都会慢慢变成一种能被智能体进入的环境。

文档不再只是给人看的文档，也要能被智能体读懂。

流程不再只是会议里讲的流程，也要能被智能体执行到某一步。

测试不再只是研发最后补的东西，而是让智能体知道自己有没有做对的反馈系统。

权限不再只是账号后台的开关，而是组织把风险写进系统的边界。

这才是深层变化。

不是「一个工具变强了」。

是公司开始重新设计自己，设计成一个强模型可以进入、可以工作、可以被约束、可以被审查的地方。

我觉得这才是李想那段访谈真正有价值的地方。

他说 人工智能公司像人体结构，不是为了搞一个漂亮比喻。

而是在提醒我们，不要再用老的部门表去看新的公司。

你不能只问，Anthropic 有多少工程师，多少产品经理，多少销售。

你要问，它的大脑在哪里，手脚在哪里，感官在哪里，记忆在哪里，免疫系统在哪里。

更重要的是，它们之间怎么协作。

这也是为什么我觉得，Claude Code 这件事不能只当产品新闻看。

它是一个窗口。

透过这个窗口，我们能看到 Anthropic 想把 Claude 变成什么。

不是更会聊天。

不是更会补代码。

而是一个能进入真实世界工作环境的强模型。

当然，这里面也有很多没被证明的东西。

Anthropic 官方给出的客户案例，毕竟还是厂商案例，不是独立审计报告。Stripe、Ramp、Wiz、Rakuten 那些数据，我会把它们当作方向信号，而不是当作绝对真理。

Claude Cowork 也一样，它能不能真的在大规模知识工作里稳定跑起来，还要看权限、误操作、文件污染、提示注入、责任归属这些硬问题。

我自己也还在摸索。

但就目前公开材料看，我越来越觉得，Anthropic 的故事不是「做了一个厉害的写代码工具」。

而是它找到了一条很聪明的路。

先在代码这个最容易验证的环境里，让强模型学会行动。

再把这套行动能力迁移到更大的知识工作环境。

同时不断给它补边界，补记忆，补评估，补人工确认。

这个路线，可能才是未来 人工智能公司最核心的竞争力。

不是模型参数，不是聊天界面，也不是某个单点功能。

是它能不能把强模型放进真实组织里，还不把组织搞乱。

大时代啊，朋友们。

以前我们讨论软件，是讨论人怎么使用软件。

现在我们可能要开始讨论，软件怎么使用软件，人怎么审判软件。

这个变化听起来有点绕。

但你想想看，Claude Code 在代码库里改文件，跑测试，修持续集成问题。Claude Cowork 在本地文件和应用里整理资料，生成交付物。OpenAI 在讲仓库知识要变成智能体能读的地图。Seed 在把能力版图拆成模型、基础设施、视觉、语音、机器人和负责任人工智能。

这些线索放在一起，其实都在指向同一个未来。

公司不再只是人的组织。

公司会慢慢变成，人和智能体共同工作的环境。

而一个真正厉害的 人工智能公司，可能不是最会讲模型故事的公司。

而是最早学会给智能体造身体，造神经，造免疫系统的公司。

回到开头。

Claude Code 真正厉害的地方，不是 Code。

是 Claude 第一次长出了可以被组织使用的手。

以上，既然看到这里了，如果觉得不错，随手点个赞、在看、转发三连吧，如果想第一时间收到推送，也可以给我个星标。

谢谢你看我的文章，我们，下次再见。
