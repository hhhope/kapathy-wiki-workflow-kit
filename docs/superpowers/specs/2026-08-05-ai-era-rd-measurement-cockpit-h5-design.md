# AI 时代研发度量驾驶舱 H5 设计

## 1. 读者与任务

| 项目 | 定义 |
|---|---|
| 核心读者 | 公司管理层、研发负责人、产研效能负责人、AI工程平台负责人 |
| 阅读任务 | 看懂国内外行业已经走到哪里、关键证据说明什么、AI前后研发系统发生了什么、公司要观测哪些信号、建设路线如何分级 |
| 主要判断 | AI使用量只反映工具渗透；管理决策依赖价值交付、质量、稳定性、完全成本和人类注意力 |
| 输出 | 单文件、可直接打开的响应式H5/HTML；包含管理驾驶舱首屏与完整证据叙事 |
| 非目标 | 不虚构公司经营数据；不做个人绩效排名；不把行业自述当成本公司ROI承诺 |

## 2. 页面路线

采用“证据型管理简报 + 度量驾驶舱”组合。首屏给管理层驾驶舱的真实样子，后续章节解释数据来源、证据、推导逻辑、架构和建设阶段。

| 章节 | 内容 | 主要视觉 |
|---|---|---|
| 首屏：研发度量驾驶舱 | 价值、效率、质量、稳定性、成本、人类注意力六域；P0信号状态；证据口径说明 | 六域仪表区、价值流漏斗、质量护栏、异常信号 |
| 行业现场 | 国内与国外的实践成熟度和公开证据强度 | 双列行业地图、证据等级 |
| 核心证据 | Stripe、OpenAI、METR、企业RCT、Atlassian、JetBrains等 | 大数字证据卡、适用边界 |
| AI前后对比 | 效率、质量、稳定性、成本、协作、工作单元 | 对比矩阵 |
| 度量优先级 | P0必须观测、P1诊断、P2成熟期能力 | 优先级矩阵与数据来源 |
| L1-L6建设阶梯 | 辅助驾驶到研发经营系统 | 六级成熟度阶梯、每级门槛 |
| 逻辑架构 | 价值管理、工作控制、Agent编排、可信上下文、工程执行、质量治理、数据实验 | 七层架构图、数据链路 |
| 决策矩阵 | 扩大、改造、收紧、暂停 | 信号组合矩阵 |
| 证据索引 | 一手链接、研究方法、证据等级、适用边界 | 可展开引用列表 |

## 3. 首屏驾驶舱

首屏使用“样例数据”水印，展示未来真实系统应有的结构，不暗示当前公司已有数据。

| 区域 | 内容 |
|---|---|
| 顶部判断条 | 当前阶段、数据完整度、质量护栏状态、观察周期 |
| 经营核心 | 质量校正价值吞吐、Idea-to-Value、单位有效产出完全成本、ROI区间 |
| 价值流 | 需求→任务→Agent→PR→部署→价值验证；显示各阶段数量、转化、等待和损失 |
| 质量稳定性 | 变更失败率、部署返工率、逃逸缺陷、事故影响、安全异常 |
| Agent生产 | 合格任务覆盖、端到端验收成功、首次通过、人工接管、重试/CI轮次 |
| 人类注意力 | 每个验收任务主动工时、评审时间、Agent中断数、并发负荷 |
| 成本 | 许可证、模型/Token、运行环境、平台、人工验证、返工、事故；按任务/项目归集 |
| 决策区 | 本周期适合扩大、需要改造、应当收紧的场景清单 |

## 4. 证据表达

| 规则 | 实现 |
|---|---|
| 所有行业数字有来源 | 数字卡附公司/机构、时间、方法、原始链接 |
| 区分规模证据与因果证据 | 标签分为RCT、准实验、纵向观测、企业自述、工程机制 |
| 明示适用边界 | 每张证据卡提供“说明什么”和“还不能说明什么” |
| 国内材料公开证据偏弱 | 国内侧同时展示方案成熟度和证据强度，避免只排品牌 |
| 样例看板不伪装成实绩 | 所有示例数值标注“结构样例”，与行业公开数字视觉区分 |

## 5. AI前后对比口径

| 维度 | AI辅助时代以前 | Agent时代 |
|---|---|---|
| 效率 | 编码时间、人均任务、PR周期、DORA | 端到端价值流、Agent墙钟与人类主动时间分离、注意力杠杆 |
| 质量 | 人工Review、测试覆盖、缺陷 | Maker-Checker分离、Agent-to-Agent Review、验证成本、D+30存活 |
| 稳定性 | 发布频率、变更失败、恢复时间 | 原指标继续保留，增加Agent越权、门禁绕过、自动修复与部署返工 |
| 成本 | 人力、平台、云资源 | 模型、Token、沙箱、上下文、重试、评审、返工、事故的完全成本 |
| 工作单元 | 代码、提交、PR | 有验收标准的任务、项目、价值流 |
| 协作 | 人与人交接 | 人定目标和边界，Agent执行，独立审查，人在判断点接管 |

## 6. 度量优先级

| 优先级 | 范围 | 进入驾驶舱的条件 |
|---|---|---|
| P0 | 价值流主键、Idea-to-Value、已验收上线吞吐、质量稳定性、完全成本、人类主动工时、Agent端到端成功/接管 | 第一阶段必须建立；缺失时不发布ROI结论 |
| P1 | 首次通过、重试、CI轮次、Review返工、D+7/D+30存活、上下文鲜度、开发体验 | 用于解释P0变化和定位瓶颈 |
| P2 | 多Agent交接、模型路由、任务复杂度预测、组合级价值归因、边际成本曲线 | 数据链稳定后建设 |

## 7. L1-L6建设模型

| 等级 | 工作方式 | 主要能力 | 进入下一级门槛 |
|---:|---|---|---|
| L1 | 个人辅助驾驶 | 补全、问答、代码解释 | 使用合规、基础采纳与体验可观察 |
| L2 | 受控任务辅助 | AI生成测试、文档、受限代码；人全程主导 | 工作项与AI事件可关联，质量未恶化 |
| L3 | 任务级Agent | Agent从任务到PR，人在计划/合并点确认 | 端到端成功、接管、成本和质量可量化 |
| L4 | 流程级协同 | 编码、测试、评审、CI Agent协同 | 独立审查、隔离环境、证据门禁和重试治理成熟 |
| L5 | 多Agent生产系统 | 工作看板调度后台Agent，人管理任务组合 | 人类注意力、并发、项目成本和异常升级可控 |
| L6 | 研发经营系统 | 研发投入与业务价值、风险、能力资产闭环 | 组合级ROI可验证，扩大/改造/收紧机制持续运行 |

## 8. 技术结构

| 模块 | 责任 |
|---|---|
| 页面壳 | 顶部状态、侧边目录、章节定位、响应式布局 |
| 驾驶舱 | 六域指标、价值流、护栏、决策清单 |
| 证据模块 | 行业案例、证据等级、来源抽屉 |
| 对比模块 | AI前后研发指标变化 |
| 优先级模块 | P0/P1/P2指标和数据源 |
| 成熟度模块 | L1-L6能力、度量、门槛 |
| 架构模块 | CSS/HTML构建的七层架构和数据流，不依赖外部图库 |

实现为单文件HTML，内嵌CSS与JavaScript。交互限于章节导航、证据筛选、来源展开、桌面/移动布局，不引入持久化和外部接口。

## 9. 视觉系统

| 项目 | 方案 |
|---|---|
| 风格 | 管理驾驶舱与研究简报结合；深墨蓝底、青绿代表效率/价值、琥珀代表成本、玫红代表风险 |
| 字体 | 中文系统字体优先，等宽字体只用于数字和证据标签 |
| 层级 | 大结论、大数字、短解释、来源；减少口号和装饰性图标 |
| 图表 | 使用HTML/CSS和少量Canvas/SVG完成必要图形；图例、单位、样例水印清楚 |
| 响应式 | 1440px管理汇报、1024px笔记本、390px移动端均可阅读 |

## 10. 验收

| 类别 | 标准 |
|---|---|
| 内容 | 国内外现状、核心证据、AI前后对比、P0/P1/P2、L1-L6、逻辑架构全部呈现 |
| 证据 | Stripe等关键数字可点开一手来源；证据类型和边界可见 |
| 驾驶舱 | 首屏像可运行的AI时代度量驾驶舱；样例数据与行业事实区分 |
| 视觉 | 无遮挡、溢出、不可读标签；桌面和移动端截图检查通过 |
| 技术 | 文件直接打开可用；无外部构建依赖；控制台无错误 |
| 表达 | 使用事实、结论和口径；清理套话、空泛口号和重复修辞 |

## 11. 自检

- 无TBD或TODO。
- 页面结构覆盖用户指定的全部内容。
- 行业事实、推测指标、样例驾驶舱三类信息有清楚区分。
