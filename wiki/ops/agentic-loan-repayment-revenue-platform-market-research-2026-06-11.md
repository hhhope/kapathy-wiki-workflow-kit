# 贷款还款 Agent 收入平台 / Market Research

## Trigger

用户要求把 Agent 支付和贷款还款订单数据增收结合，形成新的组合场景套件。本文负责市场研究、客群、替代方案和访谈计划。

## Market Definition

目标市场不是泛 AI Agent，也不是泛贷款系统，而是：

> 已有放款、还款、清算订单的贷款机构或服务商，需要用 Agent 提升还款运营效率，并希望 Agent 服务能够被计量、定价、分账和复盘。

市场判断：

- 贷款还款是高频、规则多、结果可量化的 Agent 场景；
- Agent 支付能力在这里承担 B 端服务收费，不是直接替代借款人还款支付；
- 首批客户更可能来自已有贷款、支付、清算或贷后服务链路。

## Market Segments

### Segment 1: 高订单量消费金融 / 小贷 / 助贷平台

概览：

第一优先客群。它们有大量还款失败、账单咨询、复贷运营和对账任务，适合用历史订单做 Agent 回放。

决策角色：

- 业务负责人；
- 贷后负责人；
- 客服负责人；
- 财务对账负责人；
- 产品运营负责人；
- 数据负责人。

Jobs-to-be-Done：

- 我想让 Agent 预处理还款失败订单；
- 我想减少账单解释和客服重复劳动；
- 我想找出对账差错；
- 我想知道 Agent 是否真的带来增收或降本；
- 我想用可审计方式推进 AI 试点。

痛点：

- 人工运营处理不过来；
- AI 试点难以证明 ROI；
- 数据分散；
- 合规不敢放开自动化；
- 通用 Agent 工具不懂贷款还款语义。

产品适配：

高。适合第一个付费试点。

采用障碍：

- 数据安全和授权；
- 触达审批；
- 归因争议；
- 内部跨部门协调。

### Segment 2: 贷款科技服务商 / 贷后服务商

概览：

第二优先客群。它们能把还款 Agent 服务打包卖给多个贷款机构，需要白标、多租户、计费和分账。

决策角色：

- 解决方案负责人；
- 产品负责人；
- 商务负责人；
- 客户成功负责人；
- 交付负责人。

Jobs-to-be-Done：

- 我想新增一个可复制的 Agent 增值产品；
- 我想按客户、模块、订单和效果收费；
- 我想减少人工交付；
- 我想用分账报表管理合作收益。

痛点：

- 每个贷款机构流程不同；
- 项目交付重；
- 收费模式停留在项目费；
- 缺少 Agent 效果证明。

产品适配：

高，但要求多租户和白标能力。

采用障碍：

- 客户数据边界；
- 服务商与贷款机构的责任划分；
- 白标和定制需求容易扩大范围。

### Segment 3: 支付 / 清算服务商

概览：

可作为渠道和能力承载方。它们掌握部分还款支付和清算数据，也希望从通道费率竞争进入行业解决方案。

决策角色：

- 金融行业方案负责人；
- 支付产品负责人；
- 清算产品负责人；
- 大客户销售负责人。

Jobs-to-be-Done：

- 我想提升贷款客户的交易成功率；
- 我想用 Agent 降低客户对账和客服成本；
- 我想把支付通道升级为行业增值服务；
- 我想增加客户粘性和非通道收入。

痛点：

- 只靠通道费率竞争；
- 不掌握完整贷款账务；
- 缺少贷后运营语义；
- AI 能力难以直接收费。

产品适配：

中高。适合作为 GTM 合作伙伴或联合方案。

采用障碍：

- 需要贷款机构回传订单结果；
- 不能越界处理贷款决策；
- 合作协议和数据用途复杂。

### Segment 4: 银行零售信贷部门

概览：

高价值但进入慢。适合后续从账单解释、对账差错、资产表现分析等低风险模块切入。

决策角色：

- 零售信贷负责人；
- 运营管理部门；
- 风险部门；
- 财务清算部门；
- 信息科技部门；
- 合规部门。

Jobs-to-be-Done：

- 我想安全地试点 Agent；
- 我想提升客户服务和对账效率；
- 我想保留完整审计链路；
- 我想避免 Agent 越权。

痛点：

- 采购慢；
- 安全审批严格；
- 自动化触达敏感；
- 与现有系统集成周期长。

产品适配：

中。不是第一波，但成熟后价值高。

采用障碍：

- 私有化或专有云要求；
- 合规和审计要求；
- 内部系统接口复杂。

### Segment 5: AI Agent 金融解决方案创业团队

概览：

这类团队可能已经在做金融客服、贷后运营、对账 Agent，但缺少垂直计费、分账和结果归因能力。

决策角色：

- 创始人；
- 产品负责人；
- 解决方案负责人。

Jobs-to-be-Done：

- 我想快速把 Agent 服务卖给金融客户；
- 我想按任务、订单、坐席或效果收费；
- 我想证明 Agent 价值；
- 我想避免自研计费系统。

痛点：

- 通用支付工具不懂 Agent 任务；
- 金融客户要求审计和证据；
- 结果归因难；
- 早期工程资源有限。

产品适配：

中高。可作为生态客户，但早期要避免变成通用 Agent billing。

采用障碍：

- 他们未必掌握最终订单数据；
- 客户交付链路复杂；
- 可能要求过多通用 Agent 平台能力。

## Segment Priority

| Priority | Segment | Reason | First Offer |
|---|---|---|---|
| 1 | 消费金融 / 小贷 / 助贷平台 | 有订单、有痛点、有结果 | Agent 回放 + 人机试点 |
| 2 | 贷款科技 / 贷后服务商 | 可复制、可白标 | 多租户 Agent 工作台 + 分账报表 |

## Competitive Landscape

### Alternative 1: 通用 Agent 平台

优势：

- Agent 编排、工具调用、知识库、自动化能力强；
- 能快速做原型。

弱点：

- 不懂贷款还款订单语义；
- 不内置还款恢复、对账差错、复贷边界；
- 不提供订单级价值归因和金融场景计费。

差异：

- 本产品把 Agent 任务绑定贷款订单、证据链和计费项。

### Alternative 2: 通用订阅 / Billing 平台

优势：

- 支付、订阅、用量计费、账单能力成熟；
- 生态完整。

弱点：

- 不理解 Agent 任务结果；
- 不理解贷款还款生命周期；
- 很难按恢复金额、差错追回、人工确认结果计费。

差异：

- 本产品把 Agent 活动、贷款订单和结果归因变成账单。

### Alternative 3: 贷款核心 / 贷后系统

优势：

- 已在业务流程中；
- 掌握账务和还款计划。

弱点：

- Agent 能力弱；
- 计费和分账不是核心；
- 策略效果归因通常不足。

差异：

- 本产品作为增值层接在贷款核心之上，不替代核心账务。

### Alternative 4: 催收 / 贷后运营外包

优势：

- 有人工团队；
- 熟悉逾期处理；
- 能承接运营动作。

弱点：

- AI 计费和任务账本弱；
- 容易被理解为催收，不利于早期合规定位；
- 预防性还款恢复、账单解释和对账差错不一定是重点。

差异：

- 本产品优先处理宽限期内恢复、账单解释、对账和人机协同，不把强催收作为主卖点。

### Alternative 5: 内部 BI + RPA

优势：

- 成本低；
- 内部控制强；
- 可按现有流程定制。

弱点：

- 难以生成可复用 Agent 产品；
- 难以做价值归因和外部收费；
- RPA 只执行流程，不理解业务解释和证据链。

差异：

- 本产品从一开始设计 Agent 任务账本、归因和计费。

## Positioning

一句话定位：

> 面向贷款还款场景的 Agent 运营和收入计量平台，把还款 Agent 的每次建议、确认、结果和收费依据串起来。

不是：

- 不是通用 Agent 平台；
- 不是通用支付网关；
- 不是催收外包；
- 不是征信评分；
- 不是贷款导流；
- 不是个人金融数据交易。

## Buying Triggers

客户更可能在以下时刻购买：

- 正在做 AI 试点，但无法证明 ROI；
- 还款失败和客服解释压力上升；
- 对账差错和人工处理成本高；
- 贷款科技服务商想新增 Agent 增值产品；
- 支付服务商想从通道服务升级为行业解决方案；
- 管理层要求 AI 项目有收入或降本闭环。

## Pricing Hypotheses

可测试收费：

1. Agent 回放诊断包：一次性项目费。
2. 人机协同试点包：月费 + 订单量。
3. 还款恢复分成：按恢复金额或增量恢复收费。
4. 对账差错追回分成：按确认追回金额收费。
5. Agent 任务量计费：按任务、对话、解释、差错包收费。
6. 白标多租户订阅：按机构/租户/月收费。
7. 分账报表服务：按合作方或结算周期收费。

待验证问题：

- 客户更信任固定试点费还是效果分成；
- 哪些价值可以归因到 Agent；
- 模拟账单是否能推动正式采购；
- 分账报表是否足够，不需要真实清分。

## Interview Plan

### 目标对象

- 5 位消费金融 / 小贷贷后负责人；
- 3 位客服负责人；
- 3 位财务对账负责人；
- 3 位贷款科技服务商解决方案负责人；
- 2 位支付 / 清算服务商金融行业负责人；
- 2 位金融 Agent 创业团队创始人。

### 核心问题

1. 你们现在有哪些还款运营动作最重复？
2. 哪些动作适合 Agent 先给建议、人工再确认？
3. 你们如何衡量 AI 试点是否创造价值？
4. 还款失败订单每天多少，人工能处理多少？
5. 客服账单解释工单占比多少？
6. 对账差错是否有明确追回金额？
7. 如果 Agent 生成任务账本和模拟账单，你们会怎么评估？
8. 你们能接受按任务、订单、恢复金额、订阅或混合方式收费吗？
9. 哪些 Agent 输出必须合规或主管审批？
10. 你们最不能接受 Agent 做什么？

## Research Gaps

- 缺少真实 Agent 回放样本；
- 缺少客户对 Agent 建议通过率的接受标准；
- 缺少不同收费方式的愿付价格；
- 缺少合规对人机协同边界的反馈；
- 缺少服务商白标和分账需求优先级；
- 缺少 Agent 任务和还款结果之间的归因样本。

## Next Step

市场研究下一步不是先做大规模 TAM，而是验证购买动机：

1. 找 3 家贷款客户做还款失败或对账差错访谈；
2. 找 1 家贷款科技服务商验证白标和分账；
3. 准备一个 Agent 任务账本样例和模拟账单；
4. 用样例问客户是否愿意付费试点。
