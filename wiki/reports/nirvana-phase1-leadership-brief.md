# 涅槃一期领导汇报简版

## 一、当前结论

| 项目 | 结论 |
| --- | --- |
| 汇报时点 | 截至 `2026-04-15` |
| 一期承诺终点 | `M2 基础协议支付 2026-07-23` |
| 当前总体判断 | `黄偏红` |
| 当前主线 | 一步支付、网关、账户基础能力仍是主推进带 |
| 当前核心问题 | 一期需求包大于当前稳定承接包，后段缓冲偏小 |
| 当前最关键时间点 | `2026-04-30` 补单，`2026-06-23` 绑卡，`2026-07-10` 退款，`2026-07-23` M2 |

## 二、我们现在到底提供了多少能力

说明：

- 这里不是代码完成率
- 是按“一期对客最小路径”做项目管理口径判断

| 能力层级 | 当前判断 | 占比口径 |
| --- | --- | --- |
| 稳定可对客表达 | 支付主链路基础部分 | `40%` |
| 已进入研发承接，但还不能按交付完成对外表达 | 结果反馈、基础退款、后段绑卡部分能力 | `40%` |
| 仍缺边界或缺稳定承接 | BM、分账耦合、退款治理、失败计费等 | `20%` |

一句话口径：

- `当前提供的是一期主链路能力，不是完整运营闭环能力`

## 三、对客最小路径

| 步骤 | 当前能做什么 | 当前缺什么 |
| --- | --- | --- |
| 开通与接入准备 | 基础能力已承接，可支持一期主链路接入准备 | 口径还没完全统一到接口级别 |
| 发起支付 | 一步支付主路径已形成最明确能力 | 预支付/确认支付未闭环 |
| 获取支付结果 | 查询、通知、通知清算已有承接 | 补单、补发清算、统一口径未完成 |
| 发起基础退款 | 已有基础退款承接 | 退款审核、批量退款、BM 退款治理未闭环 |
| 做运营闭环 | 可支持部分内部推进 | BM 对账、回单、分账耦合能力不足 |

## 四、当前最关键 gap

| gap | 具体问题 | 影响 |
| --- | --- | --- |
| 主链路收口 gap | 补单、补发清算、查询等已进入近端窗口，但状态不稳 | 直接影响 M2 主线可信度 |
| 退款 gap | 基础退款排到 `2026-07-10`，距 M2 仅剩 `13` 天缓冲 | 影响 M2 末端收口 |
| BM gap | 需求完整，但技术目前只承接了部分查询 | 影响对客口径和运营闭环 |
| 分账耦合 gap | 协议支付用于分账、分账退款、计费归属还没稳定边界 | 持续吞主链路资源 |
| 口径 gap | 周报“100%”、测试口径、技术排期不一致 | 汇报和对客口径容易失真 |

## 五、当前资源问题

| 资源问题 | 当前表现 | 影响 |
| --- | --- | --- |
| 关键研发复用 | 协议支付主链路和分账核心共用关键人 | 主链路收口被持续挤压 |
| 网关资源未释放 | 网关仍在做 `NACOS`、回归、压测 | 不能视为已完成资源 |
| BM 承接不足 | 需求完整，但没有完整独立承接带 | 运营能力不足 |
| 测试窗口紧张 | 主链路、退款、绑卡都压在后段 | 缓冲容易被吃掉 |
| 产品边界未拍板 | 分账退款、失败计费、BM 范围未冻结 | 排期真实性下降 |

## 六、现在我要什么

| 诉求 | 为什么要 | 不给会怎样 |
| --- | --- | --- |
| `1` 个协议支付主链路专注研发位 | 保补单、补发清算、查询、通知收口 | M2 主链路继续被挤压 |
| `1` 个 BM / 运营侧研发位 | 把查询、对账、回单、退款入口独立成包 | BM 永远挂在主链路后面 |
| `1` 个测试倾斜窗口或专门测试位 | 保主链路和基础退款回归 | 后段缓冲继续被吃掉 |
| `2026-04-18` 前完成边界拍板 | 解决 BM、退款治理、分账耦合、失败计费是否纳入一期 | 没有边界，排期不可信 |

## 七、需要领导拍板的事

| 事项 | 建议 | 不拍板的后果 |
| --- | --- | --- |
| BM 对账 / 回单是否纳入一期必交 | 单独成包，明确是否一期必交 | 一期对客范围继续不清 |
| 退款审核 / 批量退款是否纳入一期必交 | 与基础退款拆层管理 | 退款范围持续失真 |
| 协议支付用于分账是否属于一期闭环 | 单列为跨模块确认项 | 主链路资源继续被吞 |
| 分账退款按旧方案还是重评后方案走 | 先出唯一口径 | 退款与分账边界一直不稳 |
| 失败计费是否纳入一期 | 若无稳定承接，不纳入一期承诺 | 计费边界持续失真 |

## 八、汇报时我会怎么说

- 一期主链路还可以保，但已经不是绿灯
- 当前能稳定对外表达的能力大约是 `40%`
- 另外 `40%` 已进入研发承接，但还不能按交付完成对外表达
- 剩余 `20%` 仍缺边界或缺稳定承接
- 现在最重要的不是继续扩需求，而是保主链路、拆 BM、拆退款层级、冻结分账耦合边界

## 九、一句话总结

截至 `2026-04-15`，一期不是“做不出来”，而是“如果不马上收口边界和补最小资源，就会从可控黄灯滑向不可控红灯”。
