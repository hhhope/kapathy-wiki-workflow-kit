AI Agent 时代产研协作观察报

262 个 source entries 之后，行业真正争论的不是工具，而是谁定义目标、谁承担判断、谁审查结果、谁拥有作业系统。

头版判断

产研协作正在从人力流水线，变成人机作业系统。

Agent 不是把工程师变快的插件。它把 ticket、spec、PR、CI、eval、wiki 变成可执行对象。人不再只负责把上下文传给下一个人，而要负责目标、边界、判断和后果。

旧问题：怎么让人更快交付？

产品、设计、工程、测试按顺序接力。上下文靠会议和文档搬运，质量靠末端验收兜底。

新问题：怎么让系统可执行、可审查、可沉淀？

人定义目标和判断边界，agent 执行和自证，结果进入 PR、review packet、eval、wiki、rules。

行业在争什么

debate map, not word cloud

1. Coding solved 了吗？

速度派代码生成成本快速下降，工程师可以同时管理多个 agent，PR 数和原型速度会暴涨。
责任派专业软件不只是写代码。架构、安全、测试、回滚、线上后果仍然要人承担。

信号源：OpenAI Codex / Symphony、Boris Cherny、Karpathy、Stack Overflow、Practical AI。

2. PM 会消失吗？

压缩派当设计和工程都能直接产出可运行原型，传统转述型 PM 价值下降。
判断派目标定义、用户取舍、验收标准、非目标和发布判断更值钱。

信号源：Keith Rabois、Cat Wu、Teresa Torres、Notion / Figma / Intercom 的 How I AI 讨论。

3. 小团队会替代大组织吗？

密度派10 人公司、one-person company、OPD / barrel 叙事都指向更高组织密度。
治理派企业仍需要权限、审计、合规、数据边界、平台工程和责任链。

信号源：PayPal / Keith Rabois、Microsoft Frontier Firm、IBM operating model、Deloitte、Gartner。

4. Agent 是员工还是工具？

员工派agent 像团队成员，可以接 issue、查代码、跑测试、提交 PR。
对象派更准确地说，agent 是受权限、上下文、测试、审查约束的作业对象。

信号源：GitHub Copilot coding agent、Atlassian Rovo、JetBrains Central、Coder Agents、Block guardrails。

争议二维图：行业不是一条线，而是两条轴在拉扯

横轴：执行自动化；纵轴：判断责任
越往右：越相信 agent 可以承担更多执行。
越往上：越强调人类判断、审查和组织责任。

低自动化 / 高责任

传统软件工程。人手写、人工审查、流程慢，但责任链清楚。

高自动化 / 高责任

目标状态。agent 执行，PR / eval / review packet 承接审查，人对判断负责。

低自动化 / 低责任

AI 试用期。大家在个人工具里尝鲜，但组织没有定义入口、权限和质量标准。

高自动化 / 低责任

危险区。代码、数据、发布、钱流都交给 agent，但没有隔离、审计和人审。

company classes
AI 厂

OpenAI / Anthropic

把 agent loop、harness、managed agents、Claude Code、Cowork 做成新的工作基础设施。核心信号是人从写每一步，变成管目标、上下文、工具和审查。

支付 / 金融

Block / Stripe / Ramp / PayPal

钱和合规让“差不多正确”不可接受。这里的重点是 eval、权限、审计、policy、OPD / barrel 这类端到端 owner。

云商

AWS / Microsoft / Google / IBM

把 agent 放进完整 SDLC、云运营、安全、企业数据和治理。它们争的是企业控制面，不只是 IDE 插件。

传统软件

GitHub / Atlassian / JetBrains / Sourcegraph

issue、Jira、PR、IDE、CI 变成 agent 工作入口。产研对象不再只是记录，而是可执行状态机。

组织样本

Shopify / Amazon / Duolingo / Coinbase

AI 进入 headcount、招聘、绩效、承包商策略和管理者期望。这里有强信号，也有强争议。

反例 / 研究

DORA / Stack Overflow / GitLab / Thoughtworks / METR

提醒我们别只看速度。信任、调试、稳定性、工具链、技术债、生产隔离会变成新的瓶颈。

作业系统变了

from pipeline to loop

旧协作：人力流水线

产品需求 人把目标写成文档
设计交互 静态稿和口头解释
工程排期 排人力，等实现
测试验收 末端发现问题
发布回流 问题再回到人手里

新协作：人机作业循环

目标和边界 人定义问题、非目标、判断归属
spec / ticket / wiki 变成 agent 可执行上下文
agent queue 检索、生成、实现、验证、整理
PR / eval / review packet 结果必须可审查、可追踪
rules / tests / skills 沉淀 失败不只返工，要写回系统

人怎么变

the scarce role is judgment
OPD / Barrel

端到端 owner

  • 把业务目标拆成可执行任务。
  • 协调产品、设计、工程、数据和 agent。
  • 对用户价值、取舍和结果负责。
Agentic Engineer

管理 agent 的工程师

  • 设计上下文、权限、工具、测试和回滚。
  • 审查 agent 输出是否真的满足目标。
  • 把失败沉淀成 guardrail、eval、skill、lint。
Manager

作业系统设计者

  • 决定哪些工作进入 agent 队列。
  • 设计审查节点、责任边界和指标。
  • 看吞吐、质量、成本、风险，而不是只看省了几小时。

我们应该怎么做

local operating principles

三条原则

  • 目标人定。业务目标、用户价值、优先级、风险承受度不能交给 agent。
  • 过程可委托。检索、整理、生成、实现、验证、回放可以交给 agent。
  • 结果可审计。所有输出必须进入 PR、review packet、eval、wiki、日志这类可追踪对象。

第一条试点链路

  • 从会议材料、文章或需求进入。
  • 沉淀成 spec / wiki / issue。
  • agent 产出草稿、代码改动或 review packet。
  • 人审查判断，失败写回规则、测试、skill、wiki。
