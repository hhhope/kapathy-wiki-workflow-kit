# AI 作图不要直接出图：参考图驱动的高质量图片生成工作流

很多人用 AI 作图时，第一反应是把需求一次性丢给模型：

> 参考这张图，帮我生成一张类似风格的海报，内容换成这个主题。

这类需求看起来很完整：有参考图、有主题、有文字、有风格要求。但实际生成时，经常会出现几个问题：

- 模型直接出图，没先理解参考图版式。
- 文字漏掉、错位、乱码，尤其是中文长文本。
- 主题元素混乱，旧图里的品牌或无关元素没有清干净。
- 版式不像参考图，只是颜色和氛围有点像。
- 用户想要的是“可控表达”，模型却只做了“视觉想象”。

这不是简单的 prompt 写得不够长，也不是某个模型一定不行。核心问题是：**AI 作图不应该从“生成图片”开始，而应该从“拆解表达结构”开始。**

## 一、失败路径：把参考图、内容、生成动作混在一起

常见错误流程是：

1. 给一张参考图。
2. 给一段业务内容或 MD。
3. 让模型“基于这个生成图片”。

问题在于，参考图里包含的是 **版式信息**，MD 或口述里包含的是 **内容信息**，最终图片需要的是 **表达信息**。

如果直接生成，模型会同时猜三件事：

- 参考图到底哪些要保留？
- 新内容应该放到哪里？
- 哪些文字必须准确，哪些只是视觉氛围？

这会导致模型“看起来很努力”，但结果不可控。

尤其是海报、知识卡、长图、一图流这类内容密集型图片，不能把 prompt 写成一大段愿望清单。应该先拆结构，再合成。

## 二、正确路径：参考图驱动的五步工作流

推荐流程是：

```text
参考图
  ↓
反推版式 Prompt
  ↓
拆解内容字段
  ↓
合成最终图片 Prompt
  ↓
人工确认后再生成图片
```

### 1. 先反推参考图版式

不要急着生成图。第一步应该让 AI 只做一件事：

> 请分析这张参考图，提取可复用的版式 prompt，不要生成图片。

需要抽取的信息包括：

- 画幅比例：竖版 9:16、横版 16:9、方图 1:1。
- 页面结构：顶部标题区、中部卡片区、底部信息区。
- 模块数量：几个按钮、几张卡片、几栏信息。
- 视觉元素：右上角 3D 场景、图标、背景纹理、光效。
- 风格语言：科技感、金融感、手绘感、杂志感、白皮书感。
- 文字层级：主标题、副标题、小标题、标签、底部说明。

这一步产出的不是图片，而是 **版式 prompt**。

### 2. 再拆 MD 或口述内容

第二步才处理业务内容。

不要把 MD 整段塞进图片 prompt。应该拆成字段：

| 字段 | 示例 |
|---|---|
| 主标题 | Stripe 演进与 AI 支付变革 |
| 副标题 | 解析 Stripe 技术架构升级与 AI 支付应用创新 |
| 引导句 | 十五年战略路径复盘；AI 时代交易能力重组 |
| 四个按钮 | API 抽象工程、平台经营工程、风险信用工程、Agent 交易工程 |
| 四张卡片 | 交易关系可编程化、信用关系数据闭环、战略生态位持续上移、AI 时代能力复用重组 |
| 底部信息 | 时间、地点、报名方式、标语 |
| 禁止项 | 不出现 Anthropic、Claude、乱码、旧图残留元素 |

这一步的目标是：**让每个内容都有明确位置，而不是让模型自己猜。**

### 3. 合成最终图片 Prompt

第三步把“版式 prompt”和“内容字段”合成。

一个好的最终 prompt 应该包括：

- 版式锁定。
- 逐模块文字。
- 视觉风格。
- 生成约束。
- 禁止项。
- 验收标准。

不是简单说“参考这张图”，而是明确：

> 保留参考图的结构比例和模块位置，但所有文字与主题元素替换为新内容。

### 4. 人先确认 Prompt，不要立刻出图

这一步非常重要。

当需求涉及大量中文、明确版式、品牌替换、会议时间地点等信息时，模型不应该直接生成图片。

正确做法是：

> 先输出最终图片 prompt，请人确认内容和位置；确认后再生成。

这样可以在出图前拦住：

- 标题是否正确。
- 会议时间地点是否缺失。
- 旧品牌元素是否清干净。
- 模块数量是否符合参考图。
- 哪些内容必须准确展示。

### 5. 出图后按清单验收

图片生成后，不要只看“好不好看”。要按验收清单看：

- 文字是否完整。
- 中文是否清晰无乱码。
- 参考图版式是否保留。
- 禁止元素是否完全没有出现。
- 主题是否围绕目标内容。
- 底部信息是否完整。
- 关键视觉元素是否替换成功。

## 三、推荐方法：Prompt、visual-agent 与图片模型分工

AI 作图不要只理解成“选一个模型生成图片”。更稳定的做法是把它拆成三层：

```text
Prompt 方法：把需求说清楚
visual-agent：把作图类型和路径选对
图片模型：负责最后生成
```

一句话概括：

> Prompt 解决“说清楚”，visual-agent 解决“选对路”，图片模型解决“画出来”。

### 方法一：Prompt 先行，把参考图和内容拆开

适合场景：

- 有参考图。
- 有 MD、口述、文章、会议材料。
- 想生成类似风格的海报、长图、知识卡、一图流。

推荐流程：

```text
参考图 → 反推版式 Prompt
内容材料 → 拆成字段
版式 Prompt + 内容字段 → 最终图片 Prompt
人工确认 → 再生成图片
```

Prompt 的重点不是写得长，而是写清楚：

- 哪些版式来自参考图。
- 哪些文字来自业务内容。
- 哪些元素必须替换。
- 哪些内容禁止出现。
- 哪些字段需要人工确认。

### 方法二：用 visual-agent 判断作图类型

当作图需求变复杂时，不应该直接问“用哪个模型”。应该先问：

> 这个图到底属于哪一类视觉表达？

我们内部的 `visual-agent` 就是做这件事的。它把常见作图任务分成几大类，每一类有不同标准。

#### 1. 流程图 / 结构图

适合：

- 支付链路。
- 资金流。
- 系统架构。
- 账户关系。
- 接口调用顺序。

推荐标准：

- 优先保证结构准确。
- 中文标签必须清晰。
- 节点和箭头不能乱。
- 适合用 SVG、架构图、流程图方式生成。

#### 2. 海报 / 封面 / 活动宣传图

适合：

- 峰会海报。
- 课程宣传。
- 分享会封面。
- 品牌主题图。

推荐标准：

- 优先保证视觉冲击力。
- 参考图版式要先拆。
- 内容必须字段化。
- 适合图片模型或 hybrid 方式。

#### 3. 知识卡 / 一图流 / 长图

适合：

- 把文章变成图。
- 把方法论变成知识卡。
- 把复杂主题变成朋友圈或飞书可读长图。

推荐标准：

- 先拆内容层级。
- 一张图只表达一个主线。
- 卡片数量、标题、标签要明确。
- 中文准确性比装饰更重要。

#### 4. H5 / HTML 视觉页

适合：

- 可滚动解释页。
- 数据看板。
- 多章节视觉报告。
- 需要浏览器验证的页面。

推荐标准：

- 适合交互和长内容。
- 不要伪装成“图片模型出图”。
- 如果最终要图片，需要明确是截图导出，而不是图片生成。

#### 5. Hybrid 图像

适合：

- 想要图片模型的质感。
- 又要求中文文字准确。
- 海报里有大量标题、标签、说明文字。

推荐标准：

- 图片模型负责背景、场景、氛围。
- 确定性排版负责中文文字。
- 避免让图片模型直接生成大量中文。

### 方法三：选择合适的图片模型

图片模型负责最后生成，不负责替你想清楚表达结构。

国内出图可以优先尝试豆包，尤其适合中文语境下的海报、封面、视觉氛围图。

我们内部复杂作图更推荐用 Codex 图像模型配合 `visual-agent`：

- Codex 负责拆参考图。
- `visual-agent` 负责判断作图类型。
- Prompt 模板负责组织内容。
- 图像模型负责生成。
- 验收清单负责检查质量。

所以推荐组合不是“单点模型”，而是：

```text
Codex / visual-agent 做前置表达设计
+
豆包或 Codex 图像模型做最终出图
+
人工确认和验收做质量兜底
```

## 四、可复制的 Prompt 模板

下面这段可以直接作为参考图驱动作图的通用模板：

```text
你是一名视觉海报 Prompt 设计师。

任务分三步执行，不要直接生成图片：

第一步：分析参考图
请提取参考图的版式结构、视觉风格、模块层级、元素位置和可复用设计语言。
只输出“版式 Prompt”，不要输出图片。

第二步：映射内容
请将我提供的 MD / 口述内容拆成图片生成字段：
主标题、副标题、引导句、模块标题、卡片标题、卡片说明、底部信息、禁止元素、待确认字段。

第三步：生成最终图片 Prompt
请把“参考图版式 Prompt”和“内容字段”合成为一条可直接用于图片模型的最终 Prompt。
要求：
- 保持参考图版式结构。
- 替换所有旧主题元素。
- 所有中文必须清晰准确。
- 不要出现无关品牌、乱码或错别字。
- 如果存在日期、地点、报名方式等未确认字段，必须标记为“待确认”，不要自行编造。

在我确认最终 Prompt 之前，不要生成图片。
```

## 五、最终结论

AI 高效作图的关键，不是把 prompt 写得更长，而是把表达拆清楚。

更可靠的方式是：

```text
参考图负责版式
MD / 口述负责内容
Prompt 负责映射
visual-agent 负责选路
人负责确认
图片模型负责生成
验收清单负责质量
```

一句话总结：

> 不要让 AI 直接猜你要什么图。先让它理解图，再让它组织内容，最后才让它生成图片。
