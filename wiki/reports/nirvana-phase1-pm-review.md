# 涅槃一期直销模式 PM 主稿

## 一、汇报结论

| 项目 | 结论 |
| --- | --- |
| 汇报范围 | 直销模式一期 |
| 汇报时间点 | 截至 `2026-04-15` |
| 原业务里程碑 | `2026-06-30`，当前已偏离 |
| 当前功能基线 | `协议支付退款测试完成 2026-07-10`，`协议支付基础能力上线 2026-07-23` |
| 当前总体判断 | 直销模式一期已具备产品上架、统一网关、收单能力和账户承接基础；BM 对账回单、分账、代销层级能力不纳入当前一期承诺 |
| 当前管理重点 | 不继续扩需求，按当前里程碑和资源条件锁定一期范围，保住 `2026-07-23` 的基础上线窗口 |

## 二、一期承诺范围

### 2.1 一期按直销模式对客最小路径管理

| 业务步骤 | 一期承诺内容 | 当前判断 |
| --- | --- | --- |
| 产品上架 | 产品子服务、产品定价、产品开通配置 | 已具备 |
| 统一接入 | 统一网关、接口路由、字段校验、环境配置 | 已有基础，仍需完成 `Nacos`、IP 白名单、压测、产品集成和多渠道收款 API 迁移 |
| 收单能力 | 当前 7 月窗口内以协议支付为主的一步支付、预支付、确认支付、结果通知、通知清算、补单、订单查询 | 当前主线 |
| 账户承接 | 待分账户、分账接收户、统一动账、分录 | 底座已形成 |
| 基础退款 | 协议支付退款 | 已纳入一期，但当前未开始 |

### 2.2 不纳入当前一期承诺的内容

| 能力项 | 当前口径 |
| --- | --- |
| BM 对账下载、BM 回单下载 | 不纳入当前一期承诺 |
| 分账、分账退款、分账关系管理 | 不纳入当前一期承诺 |
| 代销层级能力 | 只做对标，不纳入当前一期承诺 |
| 完整收益计费能力 | 当前不按对客稳定能力表达 |

## 五、当前约束

| 约束项 | 当前表现 | 管理含义 |
| --- | --- | --- |
| 统一网关未闭环 | `Nacos`、IP 白名单、压测、产品集成、API 迁移仍在排期 | 收单能力不能按“统一入口已完全就绪”表达 |
| 基础退款后置 | 当前未开始，测试完成点是 `2026-07-10` | 退款缓冲很小，直接影响 `2026-07-23` 上线窗口 |
| 账户后段能力未启动 | 结算、冻结、查询兼容仍未开始 | 账户底座能讲，账户完整承接闭环不能讲 |
| BM 范围未成包 | 交易查询、退款入口有方向，对账下载和回单下载未形成一期交付包 | 当前只能讲基础查询和入口方向，不能讲完整 BM 运营闭环 |
| 分账范围未确认 | 分账相关事项当前均未开始 | 当前不能把“支持分账”作为一期对客口径 |

## 六、直销对客现在能讲什么

| 对客主题 | 当前能讲什么 | 当前不能讲什么 |
| --- | --- | --- |
| 产品上架 | 当前能讲直销模式下的产品上架节奏和产品子服务、产品定价、开通配置基础 | 不能讲代销层级开通能力 |
| 收单能力 | 当前能讲协议支付为主的直销收单能力 | 不能讲代销多主体收单能力，也不能讲完整多产品收单矩阵 |
| 统一网关 | 当前能讲统一接入方向和基础能力已经建立 | 不能讲已完成全部迁移和压测闭环 |
| 账户承接 | 当前能讲账户底座、统一动账和基础承接能力 | 不能讲完整结算、冻结、查询兼容已经闭环 |
| 基础退款 | 当前能讲基础退款已经进入一期承诺 | 不能讲退款治理、批量退款、BM 退款运营已经具备 |
| 新 AD / BM | 当前能讲基础查询和退款入口方向 | 不能讲对账、回单和完整运营能力 |
| 分账 | 当前只能讲仍在待确认阶段 | 不能讲一期已支持分账 |

## 七、直销对标代销

| 领域 | 直销当前能力 | 代销目标能力 | 当前差异 | 一期处理口径 |
| --- | --- | --- | --- | --- |
| 产品上架域 | 产品子服务、产品定价、产品开通配置已具备 | 多层级开通、会员与商户映射、层级权限可见 | 当前缺层级会员映射和代理视角 | 一期只保直销产品上架 |
| 接入网关域 | 统一接入方向明确，当前按直销接入推进 | 多角色接入、不同层级密钥管理和统一接入 | 当前只适合讲直销接入 | 一期只保直销接入 |
| 收单域 | 当前以协议支付收单为主 | 支持代理、会员、商户多身份映射的收单发起和归属 | 当前只适合讲直销商户直连接入 | 一期保当前收单能力 |
| 退款域 | 当前基础退款已纳入一期 | 支持代理体系下退款权限、审核、批量退款和手续费口径 | 当前只能讲基础退款 | 一期只保基础退款 |
| 账户域 | 底座和统一动账可复用 | 多主体账户承接、收益归属和可见范围 | 当前只能讲底座，不讲层级账户闭环 | 一期保账户底座 |
| BM / 资金管理域 | 当前只有基础查询和退款入口方向 | 支持代理体系下查询、对账、回单、退款入口和可见范围 | 当前最容易让对客口径失真 | 一期不承诺完整 BM |
| 分账域 | 当前无稳定交付包 | 支持收益分配、分账关系、退款回退和计费归属 | 当前差异最大 | 一期不承诺 |

## 九、资源诉求

| 补 1 个收单能力研发位 | 把结果通知、补单、补发清算、订单查询从分账拉扯中保护出来 | 当前主线继续被动延后 |

## 十、汇报口径

- 当前汇报只讲直销模式一期。
- `2026-06-30` 和 `2026-09-30` 是原业务里程碑，不是当前实际交付基线。
- 当前对客最小路径是：`产品上架 -> 统一网关 -> 收单能力 -> 账户承接 -> 基础退款`。
- 当前不把 BM 对账回单、分账、代销层级能力作为一期已具备能力表达。
