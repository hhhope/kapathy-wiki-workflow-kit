# 研发数字员工画像 V1.0 白色主题 H5 设计

## 1. 目标

将以下研究成果转化为一份可独立浏览、适合桌面与移动端阅读的白色主题 H5：

- `wiki/ops/rd-digital-employee-profile-v1-2026-08-05.md`
- `wiki/sources/rd-digital-employee-agent-source-study-2026-08-05.md`
- `wiki/reports/assets/rd-digital-employee-profile-v1/rd-digital-employee-profile-v1-onepager.png`

页面需要让读者依次理解：Agent、研发 Agent、数字员工定位、画像 V1.0、运行机制，以及人与数字员工的责任边界。

## 2. 已确认判断

- 输出形式：单页滚动叙事 H5。
- 视觉主题：白色、克制、专业、信息清晰。
- 内容顺序：Agent → 研发 Agent → 数字员工 → 画像 → 运行机制 → 边界与验收。
- 已确认的一图流作为首屏之后的整体概览图使用。
- 每个主要部分增加一张横向关系图；图的形式由内容关系决定，不机械套用同一种图表。
- 章节必须先完成概念、同业和人机分工，再进入数字员工画像，不能直接从研发 Agent 跳到能力清单。
- “数字员工的一天”是最终综合案例，用一个完整研发任务回放前面所有定义、状态、SOP、Gate 和考核指标。
- 不使用“80% 替代”“零失误”“完全自主”等缺少证据的叙事。

## 3. 读者与任务

### 读者

- 研发人员与技术负责人
- 产品经理与研发管理者
- 需要判断数字员工试点范围的业务负责人

### 读者完成阅读后的行动

1. 能区分模型、工作流、Agent、研发 Agent 和数字员工。
2. 能理解研发数字员工的岗位职责、能力结构和自治边界。
3. 能看懂 Orchestration、SOP、状态机的差异与协作关系。
4. 能用画像 V1.0 选择试点任务，而不是直接讨论人员替代。

## 4. 选择的页面方向

采用“白色编辑型滚动叙事”，而非仪表盘或长图网页。

选择理由：

- 当前内容是一条概念递进链，不是实时指标系统。
- 滚动叙事可以保留研究主线，同时让横向图承担结构、顺序和边界关系。
- H5 可以在桌面端和手机端复用，并保留章节导航、滚动进度和轻量交互。

## 5. 信息架构

### 5.1 首屏 / Hero

- 主标题：研发数字员工画像 V1.0
- 控制结论：不是“会写代码的 Agent”，而是具有岗位契约、可靠交付链与工程治理的 Agent 工作系统。
- 三个关键词：可交付、可治理、可进化。
- 主动作：开始阅读。
- 次动作：查看整体一图流。

### 5.2 整体一图流

- 使用已确认的直接图片模型版本。
- 采用白色画框与轻边框，不把长图作为背景。
- 桌面端显示完整图并提供放大查看；移动端保持原比例并允许点击查看大图。
- 作用：让读者先获得全局地图，再进入分章节解释。

### 5.3 Agent 是什么、由什么组成

本章先定义对象，再解释组成，避免把 Agent 简化成模型或聊天入口。

核心判断：Agent 是有目标、有状态、有行动能力，并能根据观察结果验证、纠正或升级的受约束执行体。

横向图 A：运行闭环轴。

`目标 → 上下文 → 规划 → 行动 → 观察 → 验证 → 纠正 / 升级`

横向图 B：组成分层轴。

- 能力来源：Model。
- 身份与知识：Identity、Context、Memory。
- 行动系统：Tools / MCP、Skill / SOP、Orchestration。
- 可靠性系统：Gate / Permission、Recovery、Evaluation / Evolution。

页面必须明确：Model 决定能力上限，Harness 决定可交付下限；状态机、SOP 和工具都只是 Agent 系统的组成部分，不等于完整 Agent。

### 5.4 研发 Agent 是什么

核心判断：研发 Agent 是嵌入研发链路、以“有验收条件的变更”为工作对象的专业 Agent；代码生成只是其中一个节点。

横向图：研发交付生命周期轴。

`需求澄清 → 影响分析 → 方案 → 实现 → 测试 / 审查 → 发布准备 → 运行反馈`

每个节点显示：输入产物、Agent 动作、输出产物和进入下一步的 Gate。

### 5.5 同业研发 Agent 图谱与人机分工

本章回答两个问题：市场上已经有哪些研发 Agent，以及它们和人的边界在哪里。

同业信息在实现前用官方产品页或官方文档做一次新鲜度核验；H5 只展示核验通过的对象，不使用二手文章替代产品现状。

横向图 A：同业覆盖范围图。按研发链路覆盖深度分为：

1. 编码辅助型：补全、问答、局部修改。
2. 任务执行型：理解仓库、计划、修改、测试、提交候选变更。
3. 全流程协同型：从需求或 Issue 延伸到测试、评审、交付和运行反馈。
4. 企业研发平台型：强调权限、知识、审计、评测、组织集成和多 Agent 协同。

横向图 B：Human on the Loop 双泳道。

- Agent 主导：上下文检索、候选方案、标准实现、自动测试、证据整理、状态同步和可恢复重试。
- 人类主导：业务目标、优先级、模糊需求取舍、跨团队承诺、架构例外、生产风险接受和人员决策。
- 共同 Gate：需求定稿、高风险变更、发布放行、质量阻断和事故复盘。

### 5.6 研发数字员工的定位与必要条件

核心判断：Agent 是能力系统，研发数字员工是被组织赋予岗位契约、权限、考核和责任链的数字工作单元。

横向图 A：定位成熟度轴。

`工具 → 助手 → Agent → 研发 Agent → 研发数字员工`

横向图 B：九项必要条件检查带。

1. 稳定岗位使命。
2. 可接收的工作单与准入条件。
3. 职责、拒绝范围和升级条件。
4. 企业上下文、岗位知识和持续状态。
5. 最小化工具与权限。
6. SOP、产物契约和质量标准。
7. KPI / SLA。
8. 人类主管、关键 Gate 和事故路径。
9. 审计、成本、反馈和迭代机制。

### 5.7 画像：身份卡、行为特征与能力雷达

本章把抽象定位落到可识别、可观察、可评价的员工画像。

身份卡包含：名称、岗位使命、服务对象、工作单元、默认自治等级、责任主体和成功标准。

行为特征包含：证据优先、边界清晰、交付闭环、克制变更、可恢复、可协作和可审计。

横向图：十维能力雷达改为“横向能力带 + 详情卡”，分为四组：

1. 理解：需求理解、仓库 / 系统理解。
2. 交付：规划拆解、工程实现、测试验证。
3. 协作：工具操作、协作交接。
4. 治理：风险治理、恢复连续性、评测学习。

交互：点击能力点展示可观察行为与典型证据，不用无依据的数值评分制造伪精确。

### 5.8 员工定级

核心判断：研发数字员工按可承担责任与所需 Gate 定级，而不是按模型版本或拟人程度定级。

横向图：自治等级轴。

`A0 信息助手 → A1 建议者 → A2 受控执行者 → A3 有界交付者 → A4 持续运营者`

- 每一级显示允许动作、人类 Gate、适用任务和禁止事项。
- V1.0 聚焦 A2–A3。
- A4 使用灰色虚线，明确不是默认建设目标。
- 风险升高时自治等级必须动态下降。

### 5.9 使用场景

横向图：任务适配轴。

- 左侧优先试点：范围清晰、验收可自动化、测试完备、环境隔离的标准变更。
- 中部谨慎使用：跨模块、涉及部分生产依赖或需要业务取舍的任务。
- 右侧拒绝或人类主导：目标不稳定、不可逆数据变更、核心生产权限、安全合规后果和人员决策。

场景卡至少覆盖：缺陷修复、标准接口 / 数据任务、测试与文档补齐、依赖分析、发布准备和质量巡检。

### 5.10 如何考核研发数字员工

核心判断：考核被接受的交付结果，不考核代码行数、对话次数或 Token 数量。

横向图：`工作单输入 → Agent 过程 → Gate → 被接受的变更 → 运行反馈`

指标分为七组：

- 交付：需求前置时间、首次验收通过率、按期完成率。
- 质量：逃逸缺陷率、回滚率、验证覆盖和审查发现率。
- 人效：人工介入分钟数、澄清轮次和返工时间。
- 可靠性：断点恢复率、升级及时率和审计完整率。
- 经济性：每个被接受变更的总成本。
- 学习：同类错误复发率和评测趋势。
- 治理：越权、未经批准外部写入和生产事故。

### 5.11 用一个研发任务还原“数字员工的一天”

本章是整页的综合案例，不新增另一套概念。

示例任务：修复一个有明确复现步骤、测试环境和验收条件的后端接口缺陷，并准备可评审的候选变更；不自动合并或发布生产。

横向主图：从接单到交付的一天时间轴。

1. 09:00 接单：检查准入、目标、风险和验收条件。
2. 09:15 理解：读取代码、历史决策、日志和测试。
3. 10:00 规划：形成最小修改方案与验证计划。
4. 10:30 实现：在隔离分支修改并保存中间状态。
5. 13:30 验证：运行测试、审查差异、处理失败或回退。
6. 15:00 人类 Gate：提交证据包，由人确认例外和交付范围。
7. 16:00 交付：形成可评审候选变更，不自行批准生产发布。
8. 17:00 复盘：记录结果、成本、人工介入和可复用失败样本。

案例中同步展示：

- Orchestration 状态如何推进。
- 每个状态加载哪个 SOP。
- 哪些工具和权限被调用。
- 哪些节点触发人类 Gate。
- 失败如何恢复或升级。
- 最终使用哪些指标考核这一天。

### 5.12 结论与下一步

- 结论公式：`研发数字员工 = 岗位责任 + Agent 能力 + 工程治理`
- 下一步：用 10–20 个真实、低到中风险研发任务回放画像。
- 提供返回顶部、查看完整一图流和查看研究页的入口。

## 6. 视觉系统

### 色彩

- 背景：`#FFFFFF`
- 主要文字：接近黑色，不使用纯黑大面积压迫页面。
- 边框：浅灰。
- 主强调色：清透蓝。
- 辅助色：薄荷绿、柔和橙、淡紫。
- 红色只用于越权、禁止和高风险，不用于一般强调。

### 字体与排版

- 使用系统中文无衬线字体栈，不加载外部字体依赖。
- 大标题宽松，正文行高充足。
- 每节只保留一个主判断，段落不与图争夺注意力。
- 英文技术词保持同一排版体系，不另用装饰字体。

### 表面与间距

- 白色页面、轻边框、极浅阴影。
- 卡片圆角统一，避免过多胶囊和悬浮装饰。
- 横向图使用实线、虚线、节点和标签解释关系，不使用无意义图标。

## 7. 交互与响应式

- 顶部阅读进度条。
- 桌面端右侧章节导航，移动端折叠为顶部章节按钮。
- 使用 IntersectionObserver 实现轻量进入动效和当前章节高亮。
- 遵守 `prefers-reduced-motion`，减少动画时关闭位移效果。
- 横向图在窄屏下允许横向滚动，并显示轻量滚动提示。
- 图片支持点击放大，Esc、遮罩点击和关闭按钮均可退出。
- 所有交互控件提供键盘焦点样式和可读标签。

## 9. 错误与降级

- JavaScript 不可用时，全部内容仍按文档顺序可读。
- 一图流加载失败时显示替代文本与研究结论摘要。
- IntersectionObserver 不可用时直接显示全部板块，不阻断阅读。
- 状态机交互不可用时，所有 SOP 内容以静态列表展示。
