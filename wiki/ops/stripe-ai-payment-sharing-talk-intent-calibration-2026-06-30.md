# Stripe AI 支付分享稿意图校准

## 背景

本记录保存 2026-06-30 对 Stripe AI 支付 40-50 分钟内部分享稿的重新校准结果。

本轮不是继续修旧 H5，也不是直接生成新页面。当前核心任务是先把分享稿的章节、风格、听众目标和方法论边界定住，再派生新的 H5。

上一轮失败的主要原因是把 Superpowers 设计稿当成关键词和局部模块清单，没有把它当成读者路径和章节验收结构。后续必须避免再次把稿子写成 source atlas、产品清单或内部分析卡片。

## 已确认的交付边界

- 路线：先做分享稿，再派生 H5。
- 时长：40-50 分钟。
- 目标：给 80 人做内部分享。
- 内容密度：逐章讲稿级，而不是大纲级。
- 旧 H5 用途：只作为素材池和证据池，不作为结构模板。
- 市场规模、估值、1000 source：少量进入样本选择和证据边界，不进入主结构。
- LinkedIn 深度：5-8 个代表性人员或背景样本，用来做人员能力画像。
- JD 深度：5-8 个岗位簇，用来观察下一轮能力投入。

## 方法论约束

新稿要走 repo 的学习方法论，而不是靠文案感觉生成。

方法链路：

```text
输入材料分层
-> Stripe 公司路径重建
-> 能力累积过程追踪
-> 金融交易语言框架抽象
-> LinkedIn / JD 组织能力交叉验证
-> 读者路径改写
-> H5 视觉化
```

承重判断必须标注证据状态：

- `promoted`：可进入正文，需要来源或明确出处。
- `candidate`：只能作为分析方向，不能写成结论。
- `route-only`：只作为线索或后续阅读。
- `proof-boundary`：必须写成边界，不许升格。
- `rejected`：不进入稿子。

每章设计必须包含：

- 本章要解决的读者问题。
- 本章要证明的判断。
- 使用的方法。
- 屏幕内容。
- 讲者话术。
- 证据来源与强度。
- 不能怎么写。
- 和主线的回扣句。

## 听众意图识别

用户明确指出，分享目标不是单一的教育、传播或打气，而是混合需求，类似一个意图饼图。

当前可识别的三类意图：

| 意图 | 作用 | 当前判断 |
|---|---|---|
| 教育 | 让听众理解 AI 时代支付行业真正难在哪里。 | 必须占主导，否则稿子会变成标题党或新闻串讲。 |
| 传播 | 让听众记住一个可复述的主线和章节标题。 | 需要更强 drama 和更统一的战场叙事。 |
| 打气 | 让听众相信复杂行业仍有长期价值，做难而正确的事值得。 | 作为结尾和方法论回收，不宜压过分析。 |

后续需要继续多轮校准这个比例。不要默认用户只要知识讲解，也不要默认用户只要传播口号。标题、节奏和案例强度都要服务这个混合目标。

## 风格要求

用户对章节标题的反馈集中在三点：

1. 不要像内部分析标签。
   - 例如 `能力簇`、`材料堆叠`、`战略判断` 这类词看不懂，也没有抓眼点。
2. 不要太 AI。
   - 标题不应反复把 `AI` 或 `Agent` 放在中心。AI 是变化压力，不是全篇主角。
3. 要有统一的战场叙事和 drama。
   - 章节要有冲突感、位置感、推进感，而不是平铺的报告标题。

已形成的风格方向：

```text
战场 -> 壁垒 -> 阵地 -> 纵深 -> 战斗力 -> 新战线 -> 下一块战场 -> 回到我们
```

这不是为了煽动，而是为了让 40-50 分钟分享有清晰推进。

## 已确认的章节标题

当前已确认采用以下章节标题体系：

1. **战场上移：支付公司争夺的不是收款，而是交易定义权**
2. **为什么 Stripe 站在战场中央**
3. **真正的壁垒：谁来定义金融交易语言**
4. **第一块阵地：Stripe 先拿下开发者接口**
5. **纵深推进：从支付接入打到商户经营和金融运营**
6. **战斗力来自哪里：Stripe 背后是什么样的人**
7. **新战线在哪里：从招聘看 Stripe 的下一轮投入**
8. **下一块战场：交易自动化会从哪里突破**
9. **回到我们：复杂行业先统一语言，再追求速度**

其中：

- 第 3 章标题经历多轮校准，最终选择 `真正的壁垒：谁来定义金融交易语言`，因为它比 `支付功能会变便宜，交易语言不会` 更专业，也能承接交易定义权。
- 第 5 章方向已确认：时间和产品必须讲，但每个时间和产品都要绑定战略选择、客户问题和能力沉淀。它不能变成抽象战略三问，也不能变成产品清单。
- 第 8 章仍需后续继续校准。当前标题方向是战场叙事，但是否足够专业、抓眼、避免 AI 化，还需要在下一轮展开时复核。

## 第 5 章特别约束

用户明确纠正：第 5 章不是不要时间线和产品，而是时间和产品要与战略绑定。

这一章后续应按如下结构展开：

```text
时间阶段
-> 当时服务谁
-> 这个客户或场景有什么难问题
-> Stripe 推出或补齐了哪些产品
-> 这些产品沉淀了什么能力
-> 这些能力后来如何被 AI / agentic commerce / 自动化交易复用
```

第 5 章要证明：

> Stripe 的产品扩张不是横向堆功能，而是围绕更复杂的交易关系持续沉淀能力。

## 后续工作方法

下一轮不要直接写完整稿。应先继续做意图识别和章节展开校准：

1. 先确认听众意图饼图：教育、传播、打气分别占多少。
2. 再确认标题体系是否既有 drama 又不失专业。
3. 逐章展开讲稿结构，每章先过用户确认。
4. 对第 2、3、5、8 章保持重点复核，因为这些章最容易漂移。
5. 设计稿通过后，再写 Superpowers design doc。
6. design doc 经用户 review 后，再进入 implementation plan。

## 当前开放问题

- 80 人听众具体构成是什么：产品、技术、运营、管理层还是混合？
- 分享目标的比例如何分配：教育、传播、打气各占多少？
- 第 8 章标题是否需要继续提升专业度和抓眼度？
- LinkedIn 人员样本和 JD 岗位簇的证据来源是否已经足够，还是需要先补样本读取？
