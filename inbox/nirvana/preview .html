三、技术目标

技术层 组件 / 改造项 当前作用 目标
接入层 统一网关 / 防腐层 接口规范、签名、加密、路由、权限、限流、错误码、IP 白名单、Nacos、对客接入方式与商用范围澄清 统一入口、统一治理、统一接入标准，并把对客方式、商用范围和 Nacos 回归一起闭环，支撑 高可用 与 高扩展
事件层 事件中心 替代单纯通知思路，承接开户通知、会员状态变更，账户状态变更等分润通知、渠道成本、状态推进、补偿处理 实现解耦、削峰、补偿与异步化，支撑 高可用 与 高性能
账务层 统一动账 / 会计事件驱动 分录、余额变更、未结算、账期、结算记账、账务接口统一 统一账务口径，降低重复开发，支撑 高一致性 与 高扩展
数据层 分库分表 / 新数据源 fi-hub 分库分表迁移、在线表 + SR、新旧链路兼容 提升容量与吞吐，支撑 高性能；同时为后续统一查询提供底座
数据治理 账单统一 / 历史债务治理 解决账单问题、历史交接造成的数据割裂、查询口径不一致 这块的核心价值不是“技术升级”，而是清理历史债务，解决账单与查询可信度问题
配置治理 配置中心 / 配置迁移 关系配置、计费配置、AD/BM 配置、历史配置迁移 解决数据孤岛、配置分散、历史系统交接问题，支撑 高扩展 与高运营效率
运营层 AD / BM 查询、退款、充值记录、划拨、线下打款、关系配置、人工介入 把分散在各系统里的资金操作与运营动作收口，形成统一运营与商户资金管理承接层，避免在分账和协议支付后段形成承接空档
保障层 压测 / 切流 / 灰度 压测、切流比对预案、新老结算兼容、流量验证 降低迁移风险，支撑 高可用 与上线稳定性
技术组件换新不是目的，真正的价值是：一边支撑高可用、高性能、高扩展，一边解决历史账单、数据孤岛、历史交接割裂这些老问题。
