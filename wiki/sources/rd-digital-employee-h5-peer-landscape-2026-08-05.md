## 官方证据记录

### GitHub Copilot Chat

- **核验日期：**2026-08-05。
- **官方来源：**[GitHub Docs：About GitHub Copilot Chat](https://docs.github.com/en/copilot/concepts/chat)。
- **官方明确能力：**官方文档称 Copilot Chat 可在对话式界面提供代码建议、说明代码功能、生成单元测试并提出缺陷修复建议；其 GitHub 环境可结合 MCP 在请求下执行受限任务，例如创建分支或合并拉取请求。
- **未确认能力：**该页明确要求用户审查和验证生成代码，并警示输出可能不正确、非最优或含安全问题；未确认其可无人工复核地完成端到端交付、接受生产风险或自行定义业务目标。
- **归属类型：**编码辅助型（可在受限请求下连接部分仓库操作）。
- **H5 可展示判断：**展示为“编码建议、解释、测试与修复建议”；不得将其标为可独立交付的数字员工或 A3/A4。

### OpenAI Codex

- **核验日期：**2026-08-05。
- **官方来源：**[OpenAI：Introducing Codex](https://openai.com/index/introducing-codex/)。
- **官方明确能力：**官方介绍将 Codex 定义为可并行处理任务的云端软件工程 Agent；每项任务在预载代码库的隔离云端环境执行，可读写文件、运行测试框架、lint 和类型检查，并可编写功能、修复缺陷和提出待评审的拉取请求。
- **未确认能力：**该来源只支持“提出供评审的拉取请求”，未确认 Codex 可自动合并、自动发布生产、承担业务优先级选择或接受生产风险。
- **归属类型：**任务执行型。
- **H5 可展示判断：**展示为“有界任务执行：理解代码库、修改、验证、提交候选 PR”；H5 必须保留“候选变更待人评审/放行”的边界。

### Google Jules

- **核验日期：**2026-08-05。
- **官方来源：**[Jules Docs：Getting started](https://jules.google/docs/)；[Jules Docs：Reviewing code changes](https://jules.google/docs/code/)。
- **官方明确能力：**官方文档称 Jules 是实验性的编码 Agent，可接入 GitHub、理解代码库并自主处理修复缺陷、补充文档和新增功能；它在虚拟机中克隆代码、安装依赖、修改文件，先生成计划，用户可在改动前审阅并批准。任务后可查看 diff、补充反馈，并由用户选择发布分支或 PR；PR 创建后仍可送审或合并。
- **未确认能力：**未确认 Jules 可绕过计划批准、代码评审、合并审批或生产发布门禁；文档将其定位为实验性编码 Agent，不支持把它描述为组织授权的持续运营者。
- **归属类型：**任务执行型。
- **H5 可展示判断：**展示为“计划—隔离执行—差异/PR—人审”的任务执行链；不得写成“自动上线”或“无需人介入”。

### GitLab Duo Agent Platform

- **核验日期：**2026-08-05。
- **官方来源：**[GitLab Docs：GitLab Duo Agent Platform](https://docs.gitlab.com/user/duo_agent_platform/)；[GitLab Docs：Get started with the GitLab Duo Agent Platform](https://docs.gitlab.com/user/get_started/get_started_agent_platform/)。
- **官方明确能力：**官方文档称该平台将多个智能助手嵌入软件研发生命周期，支持与 Agent 异步协作并把代码重构、安全扫描和研究等例行任务委派给专长 Agent。其对话可访问项目的 Issue、合并请求、提交和 CI/CD 管道；官方还列出计划、代码审查、CI/CD 修复等流程能力，以及组织可为团队工作流创建自定义 Agent。
- **未确认能力：**可用功能依赖套餐、版本、开关、角色及部署形态；官方材料并不支持“所有研发阶段已自动化”“默认可部署生产”或“无需人工审批”的表述。
- **归属类型：**全流程协同型。
- **H5 可展示判断：**展示为“把计划、代码、评审与 CI/CD 上下文连接起来的多 Agent 协同形态”；在共同 Gate 标注“需求定稿、高风险变更、发布放行和事故复盘由人负责”。

### Amazon Q Developer

- **核验日期：**2026-08-05。
- **官方来源：**[AWS Docs：Reviewing code with Amazon Q Developer](https://docs.aws.amazon.com/amazonq/latest/qdeveloper-ug/code-reviews.html)；[AWS Docs：Identity and access management for Amazon Q Developer](https://docs.aws.amazon.com/amazonq/latest/qdeveloper-ug/security-iam.html)。
- **官方明确能力：**官方文档称 Amazon Q Developer 可在研发周期中审查代码库的安全漏洞与代码质量问题，且可检查 SAST、密钥泄露、IaC 配置/合规问题、代码质量、部署风险和第三方依赖。AWS IAM 管理员能够控制谁可认证和授权使用 Amazon Q Developer 资源，并以策略管理访问。
- **未确认能力：**上述资料未确认 Amazon Q Developer 具备组织级多 Agent 编排、从需求到生产的端到端自动交付，或能自行批准任何生产变更；代码审查的支持范围还受语言、文件类型和配额限制。
- **归属类型：**企业研发平台型（本页仅按“研发辅助 + 审查 + IAM 权限治理”证据归类）。
- **H5 可展示判断：**展示为“权限治理下的研发辅助与质量/安全审查”；不可展示为“自动发布平台”或“全流程自治平台”。

## Human on the Loop：H5 人机边界文案

> **Agent 主导可标准化、可验证、可恢复的工作：**检索上下文、形成候选方案、按已批准范围修改、运行自动化验证、整理差异与证据。
>
> **人类主导目标、取舍与责任：**业务目标和优先级、模糊需求取舍、跨团队承诺、架构例外、生产风险接受和人员决策。
>
> **共同 Gate 不省略：**需求定稿、高风险变更、发布放行、质量阻断与事故复盘必须由指定责任人确认；产品的官方功能说明不等同于组织授权。
