AI Agent Collaboration / Evidence Newspaper Draft 03 · 2026-05-11

四家公司看 Agent 协作怎么落地

这不是“大家都用 AI 工具”的故事。OpenAI、Anthropic、Stripe、Block 展示的是四种不同战略：agent-first 工程操作系统、human-AI 协作工作空间、agent-readable 商业协议、AI-native 组织制度和风险。

判断一家公司的 Agent 协作现状，先看战略，再看行为：它把哪些工作交给 agent，哪些判断留给人，哪些系统边界被改造成可执行、可验证、可追责。

OpenAI 的重点不是“派任务给 agent”，而是把研发系统本身改造成 agent 可读、可运行、可自审的操作系统。Anthropic 的重点不是“非工程师也写代码”，而是把 Claude 放进专业团队的真实工作流，让专家和 AI 共同生产 artifact。Stripe 的重点不是“聊天里买东西”，而是重写 agent 交易时代的支付、授权、风控和履约协议。Block 的重点不是“工程师用了 AI”，而是把 AI-native 组织制度化，同时暴露把效率叙事和裁员绑定的风险。

OpenAI公开写作强调“Humans steer. Agents execute.”，并把 repo、CI、review、observability、docs 变成 agent 工作系统；Codex hiring 补强平台化信号。
Anthropic公开案例覆盖 data infra、product、security、marketing、design、legal；Claude Code best practices 把协作写成 explore、plan、verify、delegate 的工作法。
StripeInstant Checkout、ACP、SPT 显示交易协作从网页界面转向 agent、用户、商家、支付网络之间的协议链。
Block工程博客给出 95% 工程师使用 AI、50 名 Champions、自动 PR 21 倍增长；公开报道显示 4000/10000 裁员。

四家公司：从战略下钻到协作行为

strategy → behavior → collaboration
OpenAI / Agent-first engineering OS

OpenAI：把研发系统本身改造成 Agent 可以工作的环境

战略选择：OpenAI 的公开写作不是在讲“工程师少写代码”，而是在讲 agent-first engineering。人类负责目标、环境、约束、反馈和判断，Codex 负责执行、验证、review、修复和推进 PR。

协作方式：repo 知识成为 system of record，AGENTS.md、docs、plans、product specs、quality docs 分层承载上下文；Codex 直接使用 gh、local scripts、repository-embedded skills，自审、响应反馈、修复构建失败。Symphony 则把 Linear 这类 issue tracker 变成控制面，每个 open task 对应 agent workspace，并处理 CI、rebase、conflict、flaky check retry 和 handoff。

章节知识卡：OpenAI 的可复用方法

核心对象研发系统，而不是单个代码任务。
人负责目标、边界、优先级、架构判断和最终合并责任。
Agent 负责执行、验证、修复、响应 review 反馈、失败重试和工作区推进。
迁移提醒先补 repo 语境、测试、观测和失败写回，再谈规模化派单。

证据标签

  • Harness Engineering：5 个月约 100 万行代码、约 1500 个 PR，早期 3 名工程师驱动 Codex，后扩大到 7 名。
  • Symphony：issue tracker 作为控制面，agent workspace、watch task board、crash/stall restart、CI/rebase/retry/handoff。
  • Codex Core Agents JD：sandbox、orchestration、stateful workflows、memory、production fleet、CI/CD、安全和开发平台。

我们学到：先别问“任务能不能进队列”。更大的问题是：我们的知识、环境、测试、观测、review 和失败写回，是否已经变成 agent 能读、能跑、能验证、能改进的工程系统。

Anthropic / Human-AI collaborative workspace

Anthropic：把 Claude 放进专业团队的真实工作流

战略选择：Anthropic 不是把 Claude Code 包装成单一研发工具，而是让 Claude 进入不同职能的具体工作流。人仍然拥有专业判断，Claude 参与探索、生成、自动化和验证。

协作方式：Infrastructure 新数据科学家让 Claude Code 读取 CLAUDE.md，解释 pipeline dependency，并说明 upstream sources 如何 feeding dashboards；Data Infrastructure 在 Kubernetes incident 中把 dashboard screenshots 交给 Claude Code，定位 pod IP exhaustion 并拿到补救命令；Growth Marketing、Product Design、Legal 则把广告生成、prototype/test、phone tree 和自助审核工具变成可运行 artifact。

章节知识卡：Anthropic 的可复用方法

核心对象专业工作流和可交付 artifact。
人负责专业语境、品味、风险判断、采用或拒绝输出。
Agent 负责探索、生成、解释、自动化、原型、定位和验证辅助。
迁移提醒不要从工具培训开始，要从每个职能最真实的工作流入口开始。

证据标签

  • How teams use Claude Code：data infra、product、security、marketing、design、legal 都有具体内部用例。
  • Claude Code best practices：explore first、plan、verify、context management、permissions、MCP、subagents。
  • Claude Code PM JD：要求 PM+工程经验，并和 research、engineering、XFN 团队一起把模型进展翻成产品能力。

我们学到：不要把它写成“职能专家能不能构建”。更准确的问题是：每个专业团队的工作流里，有没有让 AI 参与探索、生成、验证和迭代的位置，同时保留人的语境、品味和责任。

Stripe / Agent-readable commerce protocol

Stripe：把交易从人类界面改造成 Agent 可读协议

战略选择：Stripe 把 agentic commerce 定义为新的经济基础设施问题。AI 入口变成 storefront 后，交易不再是人点击网页，而是 agent 带着用户意图、身份、支付上下文进入商家系统。

协作方式：ChatGPT Instant Checkout 先支持美国 Etsy 商家，Shopify 商家后续接入；ACP 让商家用一次集成接入多个 AI agent；Shared Payment Token 按 merchant 和 cart total 限定，避免暴露真实支付凭据，同时保留风控能力。ChatGPT 把 token 和订单通过 API 交给商家，商家接受或拒绝订单，并处理收费、税务、履约、退货。

章节知识卡：Stripe 的可复用方法

核心对象跨组织交易协议和责任链。
人负责购买意图、授权边界、商家承诺和争议处理判断。
Agent 负责读取商品、携带 token、发起订单、传递上下文和触发 API。
迁移提醒涉及钱、权限、客户承诺时，先写协议和回滚，不先写对话。

证据标签

  • Instant Checkout / ACP / SPT：交易协作从网页界面转向用户、agent、商家、支付网络之间的责任链。
  • Agentic Commerce EM JD：新 API primitives、dashboard surfaces、money movement、Stripe primitives 集成。
  • Agentic Commerce Designer JD：明确面向 merchants、agents、consumers 三类界面。

我们学到：当协作跨出公司边界，最先要补的不是提示词，而是协议。涉及钱、合同、客户承诺、履约和风险的流程，都必须先做到 agent 可读、可授权、可审计、可回滚。

Block / AI-native organization system + warning

Block：工程 AI-readiness 值得学，裁员叙事必须分开看

战略选择：Block 的公开材料显示两件事同时发生：工程侧把 AI adoption 制度化，管理侧把 intelligence tools 和 smaller team 绑定。这个样本必须同时保留正面做法和组织风险。

协作方式：Block 做的是组织系统，而不是单点工具采用：95% 工程师定期使用 AI，50 名 Engineering AI Champions 投入 30% 时间做 enablement；repo 层面设置 AGENTS.md、HOWTOAI.md、agent skills、AI rules、usage tracking、CI/CD 分析和 incident/postmortem 辅助。40,000+ source files、30,000+ test files、650+ deployable services 的 monorepo 被拆成 root context 和 service-level context。

章节知识卡：Block 的可复用方法

核心对象组织 adoption 系统和工程上下文治理。
人负责组织信任、人员影响、指标解释和制度边界。
Agent 负责代码辅助、自动 PR、CI/CD 分析、incident 辅助和上下文读取。
迁移提醒学 readiness、champions、rules 和 metrics，不学把效率直接等同裁员。

证据标签

  • Block Engineering：3 个月内 AI-authored code +69%，reported time savings +37%，automated PRs +21x。
  • Block Careers：当前 0 open jobs，只作为招聘边界，不推断具体原因。
  • Guardian reporting：公开报道显示 Block 裁员 4000/10000，并把 intelligence tools 与 smaller team 叙事绑定。

我们学到：repo readiness、champions、rules、skills、指标和自动 PR 可以学；把 AI-native 直接翻译成“少人更好”不能学。协作系统升级和裁员叙事必须分开判断。

这页最终留下什么

one usable takeaway

这四家公司不能被压成“员工怎么用 AI”。它们给的是四个判断坐标：系统能不能被 agent 执行，专业工作流能不能和 AI 共同生产 artifact，跨系统交易能不能协议化，组织制度化会不会被裁员叙事污染。

  • OpenAI协作重心从写代码转向设计执行系统。把 repo、测试、观测、review、执行计划和失败写回变成 agent 可读。
  • Anthropic协作重心从需求交接转向共同生产 artifact。让专家在自己的语境里和 AI 一起探索、生成、验证，再由人判断。
  • Stripe协作重心从界面转向协议。涉及钱、权限、客户承诺和履约时，先定义接口、授权、风控、拒绝、审计和回滚。
  • Block协作重心从工具采用转向组织制度。repo readiness、champions、rules、skills 和 metrics 可以学，裁员叙事必须单独处理。
真正有用的下一步不是写泛化角色建议，而是判断我们当前更接近哪一种问题，再决定是补工程系统、补专业工作流、补协议层，还是先处理组织信任边界。
