不是把规则写满，而是让能力有路可走

`learning-capture` 不是自动写 wiki 的机器。它是交通规则和检票口； 当前 agent 是司机和施工队；wiki 是落地仓库；OpenSpec 是改道路规则的审批。 治理目标是让每一次学习、沉淀、升级都有可见边界。

ROLE MAP

四个角色，各守边界

LC

learning-capture
交通规则 + 检票口

判断是不是学习、来源类型、是否过 75 分、落 wiki 还是只留候选。它不直接绕过 agent 写规则。

AG

当前 agent
司机 + 施工队

读取仓库边界、检查 dirty tree、选择具体页面、做最小编辑、验证 diff，并说明改到哪一行。

WK

wiki
落地仓库

保存学习记录、复盘、证据和可恢复上下文。它是 observation layer，不是所有规则的发布层。

OS

OpenSpec
改道路规则的审批

当学习要升级成 AGENTS、skill hard rule、spec SHALL 或 archive-ready 结论时，必须走变更和证据门禁。

FLOW

每次学习，只走一条窄路

输入进来

  • 文章 / repo / 示例 / 会议材料
  • 先看用户意图和当前上下文
  • 不是所有链接都值得沉淀

检票判断

  • source access 是否成立
  • score 是否达到精读线
  • 能复用什么，边界是什么

最低落点

  • wiki/ops：流程和治理学习
  • wiki/examples：输出形态样例
  • OpenSpec：只处理规则升级
ANTI-DRIFT

边界不是口号，是防止偷换层级

不能看到文章就写规则

外部观点先是 candidate observation。没有本地证据，不能进 hard rule。

不能用 wiki 代替 spec

wiki 记录学习和过程；要改变默认行为，必须走 OpenSpec。

不能用 skill 绕过 agent

skill 给路由和门禁；agent 负责执行、验证、保护 dirty tree。

不能无限增值

每次只升级一个真实通过证据门的能力，不把治理变成新负担。

LADDER

从学习到规则，必须逐级上楼

1

学习记录

source、claim、evidence、local usefulness、adoption boundary、status。

2

本地证据

RED/GREEN、demo、git-like 对照、真实 replay，证明不是只会写漂亮话。

3

行为资产

通过证据门后，才考虑进入 skill、AGENTS、ADR 或 spec。

4

运行反馈

上线后继续看命中率、漂移率、漏落 wiki、误升级和用户纠偏。

治理不是压缩 context，而是降低失控概率

最终目标：让 agent 先分类、再落地、再验证、再升级。 规则少一点没关系，关键是每条路都能说明：谁判断、谁执行、落到哪里、什么时候不能越界。
