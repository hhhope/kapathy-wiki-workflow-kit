# project-weekly-report-gantt-map skill 复测

日期：`2026-04-15`

目标：验证旧版 skill 在涅槃直销模式 H5 场景下存在明确偏移点，且新版约束已经覆盖这些偏移。

## RED：旧规则下的失败样例

### 样例 1：把方向性口述写进主甘特

- 输入信号：
  - 用户口述 `4月上架收单能力，5月上架宝财通，6月上架慧收钱`
  - `xlsx` 当前 7 月主线仍然以协议支付为主
- 旧规则下的偏移：
  - 主甘特被写成 `04-30分账聚合`、`06月四方收单`
  - 方向性口述被当成当前排期事实
- 失败结论：
  - 旧 skill 没有要求先区分“当前事实 / 方向补充 / 待澄清”

### 样例 2：把源表对象改写成作者抽象名

- 输入信号：
  - 源排期对象是 `统一网关`、`协议支付交易`、`涅槃账户`、`分账`
- 旧规则下的偏移：
  - 被改写成 `开通准备`、`支付结果反馈`、`协议支付分账能力`
- 失败结论：
  - 旧 skill 只要求“管理视角”，没有要求主甘特优先贴源表业务对象

### 样例 3：把待澄清信息写成既成事实

- 输入信号：
  - 用户明确说 `会员的进度要让我澄清，现在没数据`
- 旧规则下的偏移：
  - 页面里出现 `会员开通`
  - 还一度把它抬成主甘特第一条
- 失败结论：
  - 旧 skill 没有要求对缺数据内容显式标记 `待澄清`

### 样例 4：把 `未开始` 事项画成进行中

- 输入信号：
  - `基础退款`、`分账` 在源表里是 `未开始`
- 旧规则下的偏移：
  - 因为存在日期节点，被渲染成推进中的黄色条或带行动暗示的状态
- 失败结论：
  - 旧 skill 只有颜色语义，没有写死“源状态优先于日期存在”

## GREEN：新规则后的通过标准

### 通过点 1：口述信息三层分离

- 当前事实：可进入主甘特
- 方向补充：只进入说明或对比区
- 待澄清：显式标记待补数据，不进入主甘特

预期结果：
- `4 月上架收单能力 / 5 月上架宝财通 / 6 月上架慧收钱` 只在合适的业务节奏说明中出现
- 不再自动生成新的主甘特事实节点

### 通过点 2：主甘特优先贴源表对象

预期结果：
- 使用 `统一网关`、`账户`、`收单能力`、`基础退款`、`新 AD / BM`、`分账`
- 不再优先使用 `开通准备`、`支付结果反馈`、`协议支付分账能力` 这类作者抽象名

### 通过点 3：待澄清项不再伪装成进度

预期结果：
- `会员进度` 如果无数据，只能在说明中作为待澄清信息提出
- 不再进入主甘特，也不再写成 `会员开通`

### 通过点 4：状态语义服从源表

预期结果：
- `未开始` 事项保持灰色 `Not started`
- 风险强调只能加边框或备注，不能升级成 `In progress`

## 结论

- 旧 skill 的核心缺口不是结构不够，而是没有写死：
  - 主甘特命名边界
  - 口述信息分层
  - 源状态优先级
  - 标签可投屏性
- 新 skill 已把这四类偏移写成显式规则，后续再出现同类偏移，应直接视为未遵守 skill，而不是“表达风格问题”。
