# 研发数字员工画像 V1.0 白色主题 H5 设计

## 1. 目标

将以下研究成果转化为一份可独立浏览、适合桌面与移动端阅读的白色主题 H5：

- `wiki/ops/rd-digital-employee-profile-v1-2026-08-05.md`
- `wiki/sources/rd-digital-employee-agent-source-study-2026-08-05.md`
- `wiki/reports/assets/rd-digital-employee-profile-v1/rd-digital-employee-profile-v1-onepager.png`

页面需要让读者依次理解：Agent、研发 Agent、数字员工定位、画像 V1.0、运行机制，以及人与数字员工的责任边界。

## 2. 已确认判断

- 输出形式：单页滚动叙事 H5。
- 视觉主题：白色、克制、专业、信息清晰。
- 内容顺序：Agent → 研发 Agent → 数字员工 → 画像 → 运行机制 → 边界与验收。
- 已确认的一图流作为首屏之后的整体概览图使用。
- 每个主要部分增加一张横向关系图；图的形式由内容关系决定，不机械套用同一种图表。
- 不使用“80% 替代”“零失误”“完全自主”等缺少证据的叙事。

## 3. 读者与任务

### 读者

- 研发人员与技术负责人
- 产品经理与研发管理者
- 需要判断数字员工试点范围的业务负责人

### 读者完成阅读后的行动

1. 能区分模型、工作流、Agent、研发 Agent 和数字员工。
2. 能理解研发数字员工的岗位职责、能力结构和自治边界。
3. 能看懂 Orchestration、SOP、状态机的差异与协作关系。
4. 能用画像 V1.0 选择试点任务，而不是直接讨论人员替代。

## 4. 选择的页面方向

采用“白色编辑型滚动叙事”，而非仪表盘或长图网页。

选择理由：

- 当前内容是一条概念递进链，不是实时指标系统。
- 滚动叙事可以保留研究主线，同时让横向图承担结构、顺序和边界关系。
- H5 可以在桌面端和手机端复用，并保留章节导航、滚动进度和轻量交互。

## 5. 信息架构

### 5.1 首屏 / Hero

- 主标题：研发数字员工画像 V1.0
- 控制结论：不是“会写代码的 Agent”，而是具有岗位契约、可靠交付链与工程治理的 Agent 工作系统。
- 三个关键词：可交付、可治理、可进化。
- 主动作：开始阅读。
- 次动作：查看整体一图流。

### 5.2 整体一图流

- 使用已确认的直接图片模型版本。
- 采用白色画框与轻边框，不把长图作为背景。
- 桌面端显示完整图并提供放大查看；移动端保持原比例并允许点击查看大图。
- 作用：让读者先获得全局地图，再进入分章节解释。

### 5.3 Agent：从模型到可靠执行体

核心判断：Agent 不是聊天机器人，而是有目标、有状态、有行动和反馈闭环的执行体。

横向图：`Model → Context → Plan → Action → Observe → Verify / Correct`

- 使用横向闭环轴。
- Model 与 Harness 分别标注为“能力上限”和“交付下限”。
- 图下补充可靠 Agent 的十个构件，按能力、执行、治理三组呈现。

### 5.4 研发 Agent：工作对象是变更

核心判断：代码生成只是研发交付链中的一个节点。

横向图：`需求澄清 → 影响分析 → 方案 → 实现 → 测试/审查 → 发布准备 → 运行反馈`

- 使用横向交付时间轴。
- 每个节点显示输入产物、输出产物和关键 Gate。
- 人类 Gate 高亮在需求定稿、架构例外、生产发布和质量阻断。

### 5.5 数字员工：从能力到岗位契约

核心判断：Agent 是能力系统，数字员工是组织中的可管理工作单元。

横向图：`工具 → 助手 → Agent → 研发 Agent → 研发数字员工`

- 使用成熟度阶梯轴。
- 每一级增加的不是“拟人程度”，而是目标、职责、权限、KPI、主管、升级路径和审计。
- 右侧落到九项岗位必要条件。

### 5.6 画像 V1.0：能力与自治

核心判断：画像同时描述能力、可靠性、协作方式和自治边界。

横向图：十维能力带，分为四组：

1. 理解：需求理解、系统理解。
2. 交付：规划拆解、工程实现、测试验证。
3. 协作：工具操作、协作交接。
4. 治理：风险治理、恢复连续性、评测学习。

补充自治轴：`A0 信息助手 → A1 建议者 → A2 受控执行 → A3 有界交付 → A4 持续运营`

- V1.0 聚焦 A2–A3。
- A4 以灰色和虚线表示，不作为默认目标。

### 5.7 运行机制：Orchestration、SOP 与状态机

核心判断：Orchestration 管运行时推进，SOP 管节点内的标准做法，状态机是编排的生命周期骨架。

横向图采用双泳道：

- 上泳道 Orchestration：待办 → 执行中 → 验证中 → 完成 / 失败回退 / 人工升级。
- 下泳道 SOP：每个状态关联输入条件、操作步骤、质量标准、异常处理和产物记录。

交互：点击状态节点，切换展示该节点对应的 SOP 内容；移动端改为横向滚动和点击展开。

### 5.8 边界与验收

核心判断：人定义目标并放行高风险动作，Agent 负责有界交付。

横向图：自治与风险轴。

- 左侧：可自动执行的低风险标准任务。
- 中部：需要关键 Gate 的中风险任务。
- 右侧：必须由人主导或拒绝的高风险任务。

验收指标分为：交付、质量、人效、可靠性、经济性、学习和治理。

### 5.9 结论与下一步

- 结论公式：`研发数字员工 = 岗位责任 + Agent 能力 + 工程治理`
- 下一步：用 10–20 个真实、低到中风险研发任务回放画像。
- 提供返回顶部和查看完整研究页的入口。

## 6. 视觉系统

### 色彩

- 背景：`#FFFFFF`
- 主要文字：接近黑色，不使用纯黑大面积压迫页面。
- 边框：浅灰。
- 主强调色：清透蓝。
- 辅助色：薄荷绿、柔和橙、淡紫。
- 红色只用于越权、禁止和高风险，不用于一般强调。

### 字体与排版

- 使用系统中文无衬线字体栈，不加载外部字体依赖。
- 大标题宽松，正文行高充足。
- 每节只保留一个主判断，段落不与图争夺注意力。
- 英文技术词保持同一排版体系，不另用装饰字体。

### 表面与间距

- 白色页面、轻边框、极浅阴影。
- 卡片圆角统一，避免过多胶囊和悬浮装饰。
- 横向图使用实线、虚线、节点和标签解释关系，不使用无意义图标。

## 7. 交互与响应式

- 顶部阅读进度条。
- 桌面端右侧章节导航，移动端折叠为顶部章节按钮。
- 使用 IntersectionObserver 实现轻量进入动效和当前章节高亮。
- 遵守 `prefers-reduced-motion`，减少动画时关闭位移效果。
- 横向图在窄屏下允许横向滚动，并显示轻量滚动提示。
- 图片支持点击放大，Esc、遮罩点击和关闭按钮均可退出。
- 所有交互控件提供键盘焦点样式和可读标签。

## 8. 文件结构

- `wiki/reports/rd-digital-employee-profile-v1-h5.html`：页面结构和语义内容。
- `wiki/reports/assets/rd-digital-employee-profile-v1-h5/styles.css`：白色主题、布局、响应式与动效。
- `wiki/reports/assets/rd-digital-employee-profile-v1-h5/app.js`：导航、进度、状态机交互与图片放大。
- 复用 `wiki/reports/assets/rd-digital-employee-profile-v1/rd-digital-employee-profile-v1-onepager.png`。

不增加第三方前端依赖，不新增构建步骤；页面可直接从本地文件或静态服务器打开。

## 9. 错误与降级

- JavaScript 不可用时，全部内容仍按文档顺序可读。
- 一图流加载失败时显示替代文本与研究结论摘要。
- IntersectionObserver 不可用时直接显示全部板块，不阻断阅读。
- 状态机交互不可用时，所有 SOP 内容以静态列表展示。

## 10. 验证

### 静态检查

- HTML 语义结构完整。
- 页面不存在缺失的本地资源引用。
- CSS 与 JavaScript 不依赖外部网络。
- 关键文本与画像 MD 一致。

### 运行检查

- 桌面视口：1440×1000。
- 移动视口：390×844。
- 检查滚动进度、章节高亮、状态机切换、图片放大和返回顶部。
- 检查浏览器控制台无错误。
- 检查横向图不存在文字重叠、裁切、不可控滚动和误导性空白。

## 11. 发布边界

- 本轮仅生成仓库内本地 H5 和视觉检查证据。
- 不自动同步飞书、不部署网站、不发布外部链接。
- H5 是画像 V1.0 的读者版本，不把候选判断提升为组织制度或生产授权标准。
