# Stripe AI Company Evolution H5 Live Re-anchor

## Trigger

The user rejected the current H5 framing because it still read like abstract
commentary instead of a deep research output:

- "支付 API 起点" and "第一性原理" sounded like unsupported framing.
- "AI 到底改变了哪些金融对象" sounded like an inconsistent framework label.
- The page did not clearly answer what the 1000 sources were doing.
- The visual/report style was not unified.
- A later correction rejected the market/acquisition block as isolated and asked
  for market position, acquisitions, company operations, technical events, AI
  transaction changes, and capability migration to be placed into a coherent
  system.
- A later correction rejected the market-share wording as too dry and too
  defensive. The user asked for calculated share lenses, fee/TPV conversion,
  growth visualization, color-coded timelines, and better reference material.
- The user then invoked `$superpowers:brainstorming` and rejected the current
  direction as increasingly disordered: the market-position panel was not
  reader-comprehensible, the main timeline title still read like an unprocessed
  bucket list, and implementation had continued without first redesigning the
  argument.

## Re-anchored North Star

Implementation is stopped. The H5 must be redesigned before further edits.

The H5 should behave like a research argument, not a pile of source categories:

1. Start from one explicit reader question and one explicit thesis.
2. Convert source material into a small number of analytical views that have
   different jobs.
3. Use timeline, market position, acquisition, technology, and AI transaction
   evidence to support that thesis, not as parallel modules.
4. Show growth and relative position through understandable visuals, with
   calculation formulas hidden or secondary unless the reader needs them.
5. Keep boundaries visible, but do not let disclaimers become the content.

## Rejected Framing

- Do not lead with broad phrases such as "first principles" unless the evidence
  directly supports them.
- Do not use "AI changes financial objects" as a visible reader-facing chapter
  title.
- Do not present word clouds as research depth.
- Do not imply that 1000 sources have all been read when the actual state is a
  queue with promoted evidence.

## Relationship Rule For This H5

The three main views must not read as peer modules:

1. Main timeline = what happened across company operations, market position,
   acquisitions, and technology events.
2. AI timeline = which part of the transaction chain was changed over time.
3. Comprehensive view = where each event sits between payment API,
   merchant operations, Agent commerce, token billing, stablecoin, machine
   payments, and risk control.
