# 项目管理周推进循环

这页定义“每周项目管理材料”如何进入当前 wiki，并被 agent 转成可跟进的动作和判断。

## 目标

- 把周报、排期、风险、里程碑偏移等材料变成稳定输入
- 让 agent 能从这些材料里提取主线变化、风险、待办和研发任务候选
- 保证每周推进材料不是一次性文档，而是能持续沉淀和追踪

## 固定输入

每周可投递的项目管理材料包括：

- 项目周报
- 项目排期表
- 风险清单
- 里程碑对比表
- 测试进度表
- 交付问题和阻塞项清单

这些材料可以先放进 `inbox/`，再由 agent 进行 intake。

## agent 处理顺序

1. 识别材料类型：周报 / 排期 / 风险 / 里程碑 / 测试 / 问题清单
2. 判断它属于哪个项目或主线
3. 产出最小 intake/source 记录
4. 提取五类结论：
   - 本周进展
   - 相对计划或里程碑的偏移
   - 当前风险
   - 下周动作
   - 是否需要升级为 Codex handoff
5. 把结论链接到主线页、提醒页或专项报告页

## 每周最小输出

每周至少要有以下五类产物：

- `本周进展`
  - 哪些事项推进了，哪些没有推进
- `偏移判断`
  - 相对里程碑、相对周计划、相对老板预期的偏移
- `风险清单`
  - 当前最影响推进节奏的风险
- `下周动作`
  - 下一周必须主动跟进的人和事项
- `Codex 候选`
  - 哪些事项已经成熟到可以形成研发任务

## 升级规则

### 停留在 reminder

以下情况先停留在 reminder：

- 只是提醒你去对单
- 范围还没冻结
- 验收标准不清楚
- 依赖方和 owner 还没对齐

### 升级成 Codex handoff

同时满足以下条件时，才升级成 Codex handoff：

- 已经明确是研发任务
- 有清晰目标和上下文
- 已经知道影响范围
- 能写出最小验收口径

## 页面协作关系

- 原始材料：进入 `sources` 或 `intake`
- 当前主线：进入 [主线面板](main-thread.md)
- 可执行动作：进入 [提醒面板](reminders.md)
- 研发任务：进入 `codex-handoff`
- 面向老板或管理层的输出：进入 `reports`

## 当前适配场景

- 涅槃项目这类有里程碑、跨角色、多周推进的项目
- 后续每周项目管理过进度、看风险、做承接的场景
