四家公司看 Agent 协作怎么落地

这不是“大家都用 AI 工具”的故事。OpenAI、Anthropic、Stripe、Block 展示的是四种不同的协作重排：任务控制面、跨职能构建、交易基础设施、AI-native 组织赌注。

判断一家公司的 Agent 协作现状，不看口号，看三个硬信号：它怎么组织任务，怎么招聘，怎么处理风险。

OpenAI 把工程任务抽象成可持续运行的 agent workspace；Anthropic 把 Claude Code 扩散到设计、数据、营销、法律等职能；Stripe 把商品、支付授权、风控和履约改造成 agent 可读的交易接口；Block 同时给出工程 AI-readiness 的正样本和裁员叙事的警示。四家公司不是同一条路，它们代表四种组织选择。

OpenAICodex 搜索显示 25 个岗位；Core Agents JD 指向沙箱、编排、状态、生产 fleet。
AnthropicClaude Code 内部案例覆盖产品、设计、数据、营销、法律；Claude Code PM JD 要求 PM+工程背景。
StripeAgentic Commerce 有独立设计和工程管理岗位；ACP/SPT 把交易改成 agent 可调用协议。
Block工程博客给出 95% 工程师使用 AI、50 名 Champions、自动 PR 21 倍增长；公开报道显示裁员 4000+。

四个样本，各自代表一种协作模式

company modes / 组织信号
Control Plane

OpenAI：任务进入 Agent 队列

核心不是“工程师少写代码”，而是把 issue、task board、repo、测试、CI 和 review packet 变成 agent 可以持续执行的控制面。

Builder Surface

Anthropic：职能专家变 Builder

Claude Code 的内部案例把边界推到非工程职能。会描述问题的人，开始能做原型、自动化、测试和数据可视化。

Transaction Rails

Stripe：交易系统对 Agent 可读

Agent 一旦要替人买东西，协作对象就不只是员工，而是用户、商家、agent、支付机构和履约系统之间的协议。

Org Bet + Warning

Block：组织赌注和裁员警示同时成立

Block 证明 repo readiness、champions、AI rules、自动 PR 有真实工程价值；同时也证明 AI-native 很容易被讲成粗暴裁员故事。

公司一：OpenAI 选择把 Codex 做成工程任务系统

agent queue

OpenAI

路径：从 coding assistant 变成可调度、可审查、可扩展的 agent fleet。

协作模式

工程协作从“人开多个 session 指挥 agent”转向“issue tracker 作为控制面”。Symphony 把 Linear task 映射为独立 agent workspace，agent 持续运行，人审结果。

证据：Symphony
公开数据
  • Harness Engineering 称 5 个月约 100 万行代码、约 1500 个 PR。
  • 早期 3 名工程师驱动 Codex，后扩大到 7 名。
  • 部分团队引入 Symphony 后 landed PR 增长 500%。
招聘/JD 信号

OpenAI Careers 搜索 Codex 显示 25 个岗位。Core Agents JD 不是招“会提示词的人”，而是招能做沙箱、隔离、编排、状态/记忆、生产 fleet、CI/CD、安全和开发平台的人。

边界判断

OpenAI 的方向不是取消工程，而是把工程重心移到环境、反馈回路、约束和 review。风险在于：任务抽象不清时，agent 只会更快地产生偏差。

Anthropic

路径：把 Claude Code 从工程工具扩散成跨职能工作界面。

协作模式

Claude Code 的公司内部用法说明，agentic coding 不只是加速传统开发，而是在打散技术/非技术边界。数据科学、产品设计、营销、法律都能把问题转成可运行 artifact。

证据：How teams use Claude Code
公开数据
  • 营销团队用 sub-agent 生成数百条广告变体。
  • Figma plugin 可批量生成最多 100 个广告变体。
  • Product Design 用 Claude Code 写测试、做原型、发现 edge cases。
  • Legal 做 phone tree 和自助审核工具。
招聘/JD 信号

Claude Code PM JD 要求候选人有 5 年以上 PM+工程经验，至少 1 年职业工程背景，并能和 research、engineering、XFN 团队一起把模型进展翻成产品能力。

边界判断

Anthropic 的组织方向是“职能专家具备构建能力”，不是每个人都变工程师。判断、语境、用户理解和最终责任仍在人手里。

Stripe

路径：把交易从人类界面改造成 agent 可调用的经济基础设施。

协作模式

Stripe 不是在说“内部员工怎么用 AI”，而是在重做外部交易协作：消费者给意图，agent 发现商品，商家保留商品和履约控制，支付网络提供授权、风控和结算。

证据：ACP / SPT
公开数据
  • ChatGPT Instant Checkout 先支持美国 Etsy 商家，Shopify 商家后续接入。
  • ACP 是 Stripe 与 OpenAI 共建的开放标准。
  • Shared Payment Token 按 merchant 和 cart total 限定，避免暴露真实支付凭据。
招聘/JD 信号

Agentic Commerce EM JD 明确写新 API primitives、dashboard surfaces、money movement、Stripe primitives 集成；Designer JD 明确面向 merchants、agents、consumers 三类界面。

边界判断

Stripe 的方向说明：支付领域的 agent 协作必须先机器可读、可授权、可风控、可履约。这里不能用“模型更聪明”替代协议和责任链。

Block

路径：一边做工程组织 AI-readiness，一边用 AI 解释组织缩编。

协作模式

Block 的工程路线很清楚：先让 repo 对 agent 友好，再用 Champions、AI rules、HOWTOAI、skills、RPI、自动 PR 和 CI/CD 把 agent 嵌进团队日常。

证据：Block Engineering
公开数据
  • 约 95% 工程师定期使用 AI 辅助开发。
  • 50 名 Engineering AI Champions，每人投入 30% 时间做 enablement。
  • 3 个月内 AI-authored code +69%，reported time savings +37%，automated PRs +21x。
招聘/JD 信号

当前 Block careers 页面显示 0 open jobs。搜索缓存里有 AI Engineering Tools、Advanced Insights & Modeling 等岗位痕迹，但不能按当前开放岗位使用。这个信号本身更像冻结/收缩，而不是扩招。

边界判断

公开报道显示 Block 裁员 4000+，Dorsey 将其与 intelligence tools 和更小团队联系起来。Block 的工程实践可学，裁员叙事必须作为风险处理。

这四条路不是同一个结论

what the evidence says

OpenAI 和 Anthropic 都在重排“谁能构建”

OpenAI 更像工程任务系统，从 task 到 agent workspace 再到 review；Anthropic 更像职能边界重排，让设计、数据、营销、法律都能直接产出可运行 artifact。

Stripe 把问题推进到公司外部

一旦 agent 代表用户交易，公司协作就延伸到商家目录、支付授权、风控、履约、售后和用户确认。支付公司的协作对象是协议链，不只是内部团队。

Block 是最该保留警示的一家公司

Block 的工程 enablement 有数据、有做法、有工具；但它同时把 AI-native 叙事和大规模裁员绑定在一起。这个案例不能被美化成单纯效率故事。
