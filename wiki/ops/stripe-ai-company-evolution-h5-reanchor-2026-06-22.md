## Trigger

The user rejected the current H5 framing because it still read like abstract
commentary instead of a deep research output:

- "支付 API 起点" and "第一性原理" sounded like unsupported framing.
- "AI 到底改变了哪些金融对象" sounded like an inconsistent framework label.
- The page did not clearly answer what the 1000 sources were doing.
- The visual/report style was not unified.
- A later correction rejected the market/acquisition block as isolated and asked
  for market position, acquisitions, company operations, technical events, AI
  transaction changes, and capability migration to be placed into a coherent
  system.

## Re-anchored North Star

The H5 should behave like a research control surface:

1. Show how the 1000-source queue is organized.
2. Promote only verified or explicitly bounded sources into visible claims.
3. Read company operations and technical events together.
4. Show how commercial behavior affects technical choices, and how technical
   capabilities create new commercial behavior.
5. Keep conclusions staged and evidence-bound.

## Rejected Framing

- Do not lead with broad phrases such as "first principles" unless the evidence
  directly supports them.
- Do not use "AI changes financial objects" as a visible reader-facing chapter
  title.
- Do not present word clouds as research depth.
- Do not imply that 1000 sources have all been read when the actual state is a
  queue with promoted evidence.

The three main views must not read as peer modules:

1. Main timeline = what happened across company operations, market position,

2. AI timeline = which part of the transaction chain was changed over time.
3. Comprehensive view = where each event sits between payment API,
   merchant operations, Agent commerce, token billing, stablecoin, machine
