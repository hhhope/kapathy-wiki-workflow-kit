# SVG 一图流 Skill

## 概述

从时序、交互、支付/清结算、请求响应、信息流或资金流材料中提取关键参与方和交互逻辑，生成**信息流 + 资金流**上下合并的单张 Apple 风格 SVG。

输出固定为一张图，包含：
- **上半部分：信息流** — 展示请求/响应的来回路径
- **下半部分：资金流** — 展示资金的实际流转方向

---

## Step 1：解析时序图

从用户提供的 Mermaid 时序图中提取以下信息：

### 1.1 识别核心参与方（最多 4 个节点）

将时序图中所有 participant 归类为以下角色之一：

| 角色 | 归类规则 | 颜色 | 图标字 |
|------|----------|------|--------|
| **客户 / 付款方** | 发起请求的终端用户或商户 | `#007AFF`（蓝） | 客 |
| **第三方支付机构** | 支付平台、支付服务商（如宝付、支付宝、微信支付） | `#5856D6`（紫） | 宝/付/支 |
| **银行** | 收款行、付款行、结算行 | `#34C759`（绿） | 银 |
| **清算组织** | 网联、银联、SWIFT 等清算机构 | `#FF9500`（橙） | 联/联 |

> 如有多个 participant 属于同一角色（如多个银行），合并为一个节点，副标题列出具体名称。

### 1.2 识别信息流路径

扫描时序图中的 `->>` 和 `-->>` 连线：
- 实线 `->>` = 请求/正向信息流（实线箭头）
- 虚线 `-->>` = 返回/响应（虚线箭头）
- `alt` 块中的分支 = 条件路径（需标注进入条件）

### 1.3 识别资金流路径

根据业务语义判断资金流向（不是信息流），使用上下文语义线索：
- `代付`、`付款`、`转账`、`打款` → 资金从支付机构流向银行（绿色粗实线）
- `退款`、`退还`、`冲正` → 资金回流路径（橙色实线，通常经清算机构）
- `委托`、`授权` → 非资金流转，用蓝色细虚线表示授权关系

### 1.4 识别异常/退款路径

根据异常分支、失败路径、退款语义或回退路径等结构信号判断：
- 信息流中：橙色路径（退款代付流程）
- 资金流中：橙色路径（资金经清算机构退回）

## Step 2：规划 SVG 布局

### 固定画布规格

```
总尺寸：900 × 1040px
上半（信息流）：Y 0–520
下半（资金流）：Y 520–1040
背景色：#F2F2F7
分隔线：Y=524，#D1D1D6 虚线
```

### 节点位置规则

根据识别到的节点数量（2–4 个）按以下坐标分布：

**2 个节点（水平）**
```
节点A: x=220, 节点B: x=540
```

**3 个节点（水平等距）**
```
节点A: x=62,  节点B: x=376, 节点C: x=692
```

**4 个节点（3横+1竖）**
```
上行：节点A: x=62,  节点B: x=376, 节点C: x=692
下方：节点D: x=376（清算机构，垂直方向）
```

每个节点固定规格：`148×68px，rx=18，Y=206（信息流）/ Y=726（资金流）`

清算机构节点 Y：`406（信息流）/ 910（资金流）`

### 箭头路径规则

| 方向 | 路径类型 | 说明 |
|------|----------|------|
| 水平 A→B | 直线，Y=节点中心Y-15（正向）/ Y=节点中心Y+15（返回） | 正反向错开15px避免重叠 |
| 垂直 B→D | 竖线，X=节点左1/3处（下行）/ X=节点左1/3+36（上行） | 正反向错开36px |
| 斜向 D→C | 对角线 | 清算机构→银行的退款路径 |

## Step 3：生成 SVG

按照 `references/svg-template.md` 中的代码结构生成完整 SVG。

### 必须包含的元素

**每个节点（node card）**
```svg
<g transform="translate(X, Y)">
  <rect width="148" height="68" rx="18" fill="white" filter="url(#fs)"/>
  <circle cx="35" cy="34" r="21" fill="[角色颜色]"/>
  <text x="35" y="34" dominant-baseline="central" ...>[图标字]</text>
  <text x="104" y="27" ...>[节点名称]</text>
  <text x="104" y="48" ...>[副标题]</text>
</g>
```

**箭头标签（pill label）**
```svg
<rect x="X" y="Y" width="W" height="19" rx="9.5" fill="white" filter="url(#fp)"/>
<text ...>[标签文字]</text>
```

**必须包含的 defs**
- `filter#fs`：卡片阴影（feDropShadow dx=0 dy=4 stdDeviation=12 opacity=0.07）
- `filter#fp`：标签阴影（feDropShadow dx=0 dy=2 stdDeviation=5 opacity=0.06）
- 所有用到的 `marker`（开口 V 形箭头）

### 颜色系统（严格遵守）

| 元素 | 颜色 | 用途 |
|------|------|------|
| `#007AFF` | 蓝 | 客户节点、正向请求箭头（信息流） |
| `#5856D6` | 紫 | 支付机构节点、代付请求箭头 |
| `#34C759` | 绿 | 银行节点 |
| `#FF9500` | 橙 | 清算机构节点、退款路径箭头 |
| `#30D158` | 亮绿 | 资金流中代付资金箭头（粗3px） |
| `#8E8E93` | 灰 | 返回/响应虚线箭头 |

### 箭头样式（严格遵守）

所有箭头必须使用**开口 V 形**（非实心三角）：
```svg
<marker ...>
  <path d="M1,1.5 L11,5 L1,8.5" fill="none" stroke="[颜色]" stroke-width="2"
        stroke-linejoin="round" stroke-linecap="round"/>
</marker>
```

信息流正向：`stroke-width="2"`，实线
信息流返回：`stroke-width="1.5"`，`stroke-dasharray="5,3"`
资金流代付：`stroke-width="3"`，实线（更粗体现资金量感）
资金流授权：`stroke-width="1.5"`，`stroke-dasharray="5,4"`（细虚线）

---

## Step 4：输出规范

1. 生成完整 SVG 文件，保存至 `/mnt/user-data/outputs/`
2. 文件命名：`[业务名称]_信息流_资金流.svg`
3. 使用 `present_files` 工具输出给用户
4. 附一句话说明：识别到的节点归类和路径逻辑，让用户确认是否准确

### 质量检查清单

输出前自查：
- [ ] 节点数量是否正确（不超过4个）
- [ ] 信息流箭头方向是否与时序图一致
- [ ] 资金流路径是否基于业务语义而非信息流方向
- [ ] 退款/失败路径是否用橙色标注
- [ ] 所有箭头是否有标签 pill
- [ ] 两个图例是否完整
- [ ] SVG 能否在浏览器中正常渲染（无缺失闭合标签）
