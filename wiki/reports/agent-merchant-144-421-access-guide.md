# 代运营商户开通 144 + 421 产品接入指引

> 适用对象：本次需要为特定代理商开通协议支付产品 144 和分账产品 421 的接入、产品、运营、技术同事。
>
> 结论先行：该代理商的产品开通路径比较特殊。144 需要先按协议支付对应货架开通；421 不能跟 144 混在同一个货架里开，需要再单独按 `10370560005` 货架开通。分账接收方完成进件后，还必须绑定分账关系，未绑定关系前不能发起分账。

## 1. 本次接入目标

本次需求不是普通代运营商户只开户，也不是单独开一个产品，而是要完成一条完整链路：

1. 代运营商户开户进件。
2. 为代运营商户开通协议支付产品 `144`。
3. 为同一代运营商户单独开通分账产品 `421`。
4. 分账接收方进件。
5. 分账接收方绑定代运营商户。
6. 绑定关系生效后，再发起分账交易或分账配置验证。

## 2. 涉及接口

| 序号 | 场景 | 接口/文档 | 本次用途 |
|---:|---|---|---|
| 1 | 代运营开户进件 | https://docs.baofu.com/docs/shrw/shrw-1gfsumatnb1q6 | 创建代运营商户，获取后续产品开通使用的 `uid`。 |
| 2 | 代运营开通货架 | https://docs.baofu.com/docs/shrw/shrw-1giirqfkt9q58 | 分别开通 144 和 421。注意两次产品开通的货架不同。 |
| 3 | 分账接收方进件-对私 | https://docs.baofu.com/docs/shrw/shrw-1hdh1jptu37lo | 对私分账接收方进件，可按场景同步绑定分账关系。 |
| 4 | 分账接收方进件-对公 | https://docs.baofu.com/docs/shrw/shrw-1gfsumatnb1q6 | 对公分账接收方进件，可按场景同步绑定分账关系。 |
| 5 | 分账接收方绑定代运营商户 | https://docs.baofu.com/docs/shrw/shrw-1hakar1ht6lqm | 当一个接收方需要接收多个代运营商户分账时，使用该接口单独绑定。 |

## 3. 推荐接入流程

```mermaid
flowchart LR
  A[代运营开户进件] --> B[获取 uid]
  B --> C[开通协议支付 144]
  B --> D[单独开通分账 421]
  C --> E[确认 144 开通结果]
  D --> F[确认 421 开通结果]
  E --> G[分账接收方进件]
  F --> G
  G --> H[绑定代运营商户分账关系]
  H --> I[分账能力验证]
```

接入顺序建议按上图执行。核心原因是：`uid` 是产品开通的基础，144 和 421 的产品开通参数不同，分账交易又依赖接收方和代运营商户之间的绑定关系。

## 4. 第一步：代运营开户进件

### 4.1 接口用途

先通过代运营开户进件接口创建代运营商户。开户成功后，接口返回 `uid`，后续开通 144、421 时都使用这个 `uid`。

### 4.2 本次关键参数

| 参数 | 本次建议 | 说明 |
|---|---|---|
| `merchantType` | `COMPANY` | 本次样例为企业主体。 |
| `merchantProperties` | `AGENT_MEMBER` | 标识为代运营成员商户。 |
| `createBaseInfo` | 按商户营业执照、法人、地址、联系人信息填写 | 不要在飞书中传递完整身份证、手机号、邮箱等敏感信息。 |
| `cdpMerchantBusinessInfo` | 按经营类目填写 | 包含业务类型、一级/二级类目等。 |
| `cdpMerchantBankInfo` | 按结算账户填写 | 企业商户应确保账户名与主体一致。 |
| `merchantFileInfos` | 上传文件后传文件 UUID | 文件类型和 UUID 以文件上传结果为准。 |
| `notifyUrl` | 按接入方回调地址填写 | 用于接收进件结果通知。 |

### 4.3 成功结果判断

本地样例中，开户成功响应为：

```json
{
  "success": true,
  "result": "<开户返回的uid>"
}
```

其中 `result` 即后续产品开通使用的 `uid`。生产接入时应以实际返回值为准，不要复用样例值。

## 5. 第二步：开通协议支付产品 144

### 5.1 特殊点

该代理商已经先开协议支付，因此产品 `144` 只能按协议支付对应货架开通。本地样例中，`144` 的产品开通使用：

| 字段 | 样例值 | 说明 |
|---|---|---|
| `productId` | `144` | 协议支付产品。 |
| `productModelId` | `M2503000004` | 协议支付对应货架，最终以产品侧确认为准。 |
| `uid` | 开户返回的 `uid` | 不能使用代理商父级 UID 替代。 |
| `applySerialNo` | 接入方生成 | 建议全局唯一。 |
| `signedWay` | `2` | 按接口规范填写。 |
| `signedFun` | `1` | 按接口规范填写。 |

### 5.2 请求结构示意

```json
{
  "uid": "<开户返回的uid>",
  "applySerialNo": "<产品开通申请流水号>",
  "notifyUrl": "<产品开通回调地址>",
  "signedWay": "2",
  "signedFun": "1",
  "feeRuleList": [
    {
      "productId": "144",
      "productModelId": "<协议支付对应货架>",
      "feeAcctId": "1",
      "billModel": "1",
      "beginEffectiveTime": "<生效时间>",
      "rateRuleStrategyList": [
        {
          "feeRate": "<费率>",
          "minFee": "<最低手续费>"
        }
      ]
    }
  ]
}
```

### 5.3 注意事项

1. 不要把 `144` 放到 `10370560005` 货架里开。
2. `productModelId` 以协议支付产品侧确认的货架为准；本地样例为 `M2503000004`。
3. 费率、生效时间、计费账户、结算模式应由产品/运营确认后再传。

## 6. 第三步：单独开通分账产品 421

### 6.1 特殊点

分账产品 `421` 需要单独开，不能和 `144` 混成一次产品开通。本次应按 `10370560005` 货架开通。

| 字段 | 样例值 | 说明 |
|---|---|---|
| `productId` | `421` | 分账产品。 |
| `productModelId` | `10370560005` | 本次 421 对应货架。 |
| `uid` | 开户返回的 `uid` | 与 144 使用同一代运营商户 UID。 |
| `prodExtendInfo.bankType` | `HT` | 按样例和产品要求填写。 |
| `prodExtendInfo.openSupplyInfo` | 必填扩展信息 | 包含分账相关资质、技术支持信息、比例等。 |

### 6.2 请求结构示意

```json
{
  "uid": "<开户返回的uid>",
  "applySerialNo": "<产品开通申请流水号>",
  "notifyUrl": "<产品开通回调地址，可按接口要求填写>",
  "signedWay": "2",
  "signedFun": "1",
  "feeRuleList": [
    {
      "productId": "421",
      "productModelId": "10370560005",
      "feeAcctId": "1",
      "billModel": "1",
      "beginEffectiveTime": "<生效时间>",
      "rateRuleStrategyList": [
        {
          "feeRate": "0",
          "minFee": "0",
          "maxFee": "0"
        }
      ]
    }
  ],
  "prodExtendInfo": {
    "bankType": "HT",
    "openSupplyInfo": {
      "supplyFiles": [
        {
          "fileType": "<资质文件类型>",
          "fileUuid": "<上传后返回的文件UUID>"
        }
      ],
      "techSupportPhone": "<技术支持电话>",
      "techSupportFlag": 1,
      "shareProdRatio": "<分账比例，按产品要求确认>"
    }
  }
}
```

### 6.3 成功结果判断

本地样例中，421 开通成功响应包含：

```json
{
  "success": true,
  "result": {
    "openState": "1",
    "openApplyNo": "<产品开通申请号>"
  }
}
```

验收时至少确认：

1. `success=true`。
2. `openState=1`。
3. 有产品开通申请号 `openApplyNo`。
4. 后台或产品侧能查到该 `uid` 已开通 421。

## 7. 第四步：分账接收方进件

分账产品开通后，还需要处理分账接收方。

分账接收方分为对私和对公两类：

| 接收方类型 | 接口 | 说明 |
|---|---|---|
| 对私接收方 | 分账接收方进件-对私 | 适用于个人接收方。 |
| 对公接收方 | 分账接收方进件-对公 | 适用于企业接收方。 |

分账接收方进件时，可按接口能力同步绑定分账关系。但要注意：能够同步绑定不代表可以省略关系校验。分账前必须确认接收方和代运营商户之间的绑定关系已经生效。

## 8. 第五步：绑定分账接收方与代运营商户

如果一个分账接收方只接收一个代运营商户的分账，可以在进件时同步绑定，具体以接口支持和业务配置为准。

如果一个分账接收方需要接收多家代运营商户的分账，应单独调用“分账接收方绑定代运营商户”接口。

绑定关系是分账能力的前置条件：

1. 未完成绑定关系，不能发起分账。
2. 接收方主体、账户状态、代运营商户 UID、产品 421 开通状态都要校验。
3. 一个接收方绑定多个代运营商户时，应逐一记录绑定结果，避免只进件未绑定。

## 9. 联调验收清单

| 检查项 | 验收标准 |
|---|---|
| 代运营开户 | 返回 `uid`，且商户属性为代运营成员商户。 |
| 144 产品开通 | 在协议支付对应货架下开通成功。 |
| 421 产品开通 | 在 `10370560005` 货架下单独开通成功。 |
| 421 扩展信息 | `prodExtendInfo` 按产品要求传入，资质文件、技术支持信息、分账比例完整。 |
| 分账接收方进件 | 对私/对公接收方按对应接口进件成功。 |
| 分账关系绑定 | 接收方与代运营商户绑定关系生效。 |
| 分账验证 | 具备发起分账的前置条件，异常时能定位是产品未开、接收方未进件还是关系未绑定。 |

## 10. 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 把 144 和 421 当作同一货架一次开通 | 421 可能未按正确货架生效。 | 144 按协议支付货架开，421 按 `10370560005` 单独开。 |
| 用父级代理商 UID 开产品 | 产品可能开到错误主体。 | 使用代运营开户返回的商户 `uid`。 |
| 只做分账接收方进件，不做绑定关系 | 分账发起时无有效接收关系。 | 进件后确认或单独调用绑定接口。 |
| 一个接收方接收多家分账但只绑定一家 | 部分代运营商户无法分账。 | 对每家代运营商户逐一绑定。 |
| 在文档里明文传身份证、手机号、签名报文 | 产生信息安全风险。 | 飞书中仅保留字段说明和脱敏样例。 |

## 11. 待确认事项

| 问题 | 负责人建议 |
|---|---|
| 协议支付 144 的正式 `productModelId` 是否确认为 `M2503000004` | 产品/运营 |
| 421 的 `productModelId=10370560005` 是否为该代理商唯一适用货架 | 产品/运营 |
| 421 的 `bankType=HT`、`shareProdRatio`、资质文件类型是否有生产口径 | 产品/技术 |
| 分账接收方是否需要进件时同步绑定，还是统一走单独绑定接口 | 产品/运营/接入方 |
| 一个接收方接收多家代运营商户分账时，绑定关系是否需要批量能力 | 技术/产品 |
