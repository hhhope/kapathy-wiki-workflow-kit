## 提炼出的关键事实

1. 代运营开户进件成功后返回商户 `uid`，后续产品开通均使用该 `uid`。
2. 代运营商户类型使用 `merchantType=COMPANY`、`merchantProperties=AGENT_MEMBER`。
3. 飞书接入主干口径为：协议支付产品 144 与分账产品 421 可按 `144 + 421` 一次性产品开通方案处理，两个产品作为同一次请求中的两个 `feeRuleList` 条目，`productModelId` 均使用 `10370560005`。
4. 分账产品 421 开通需要传 `prodExtendInfo.openSupplyInfo`，但 2026-06-23 口径修正为：本场景不要求传 `bankType`，也不要求传技术支持电话或 `techSupportFlag`。
5. 421 分账类产品如果需要补充产品开通附件，应在 `openSupplyInfo.supplyFiles` 中选择 `fileType=9915999`。
6. `shareProdRatio` 为订单分账产品必传，支持两位小数，取值范围 `(0,100]`；余额分账上传 `100` 即可。
7. 分账产品 421 开通成功响应中返回 `openState=1` 和 `openApplyNo`。

## 2026-06-23 补充资料口径

用户补充的沟通结论：

1. 421 产品开通不需要传银行类型。
2. 当前问题中的技术支持电话/`techSupportFlag` 不需要传。
3. 合规准入所需具体资料仍需姚世杰或合规确认。
4. 宝付代扣代运营开户所需资料包括：
   - 营业执照、对公账户、银行电子回单、法人身份证正反面、手机号、邮箱。
   - 门头照（包含门牌 logo）和办公场景照片 2 张。
   - 手机端截图、商家店铺二维码、商家店铺认证页。
   - 代运营协议、委托划扣授权书。
   - 推广代付协议。
   - 合作情况说明函。
5. 如果开户或会员创建/会员信息修改时已经送过上述第 2 至第 6 类材料，产品开通时可以不重复上传。
6. 如果未送过上述材料，且要开分账类产品，则必须补传；如果开产品但不开分账类产品，则不需要产品开通补充材料。
7. 分账类产品补充附件按销售要求的第 2 至第 6 类材料传，产品开通附件类型注意选择 `9915999`。

## `openSupplyInfo` 字段口径

| 参数名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `wechatMerchApplyFlag` | Integer | N | 微信产品必传，是否通过宝付申请，`0` 否，`1` 是。 |
| `wxAppIdSet` | array | C | `wechatMerchApplyFlag=0` 时设置，绑定数量最多 5 个。 |
| `wxAuthUrlSet` | array | C | `wechatMerchApplyFlag=0` 时设置，绑定授权目录最多 5 个。 |
| `aliMerchOwnerFlag` | Integer | C | 支付宝产品必传，`0` 否，`1` 是。 |
| `aliMerchantName` | string(64) | C | `aliMerchOwnerFlag=1` 时必传。 |
| `aliMerchantNo` | string(64) | C | `aliMerchOwnerFlag=1` 时必传。 |
| `shareProdRatio` | BigDecimal | N | 订单分账产品必传，支持两位小数，取值范围 `(0,100]`；余额分账上传 `100` 即可。 |
| `techSupportFlag` | Integer | N | `0` 否，`1` 是；当前 421 问题口径为不需要传。 |
| `supplyFiles` | array | N | 产品开通补充附件；分账类产品补充材料选择 `9915999`。 |

## 接入指引中的风险提示

1. 421 产品开通资料口径已更新，不应继续要求固定传 `bankType=HT`、技术支持电话或 `techSupportFlag=1`。
2. 产品开通附件如果走补充材料，应选择 `9915999`，不要误选经营场景附件类型替代产品开通附件。
3. 分账接收方必须完成进件和绑定关系后，才具备分账条件。
4. 如果一个分账接收方需要接收多个代运营商户的分账，应使用“分账接收方绑定代运营商户”接口逐一绑定。
5. 合规准入材料的最终必传清单仍需合规确认；本页只记录当前沟通口径和接入指引修订依据。
