AI Agent Collaboration / Company Playbook Draft 01 · 2026-05-11

四家公司告诉我们：Agent 协作不是工具接入，而是作业系统重排

OpenAI、Anthropic、Stripe、Block 给出的不是同一种答案。它们共同说明：Agent 进入公司后，真正变化的是任务入口、职能边界、交易基础设施和组织人数叙事。

头版判断

现有公司的人，不是要立刻让 Agent 多做事，而是先让工作能被正确交出去、审回来、写回去。

当前最危险的误解，是把 AI 协作理解成“人人装一个工具”。OpenAI 的样本说明，任务入口要从聊天框进入 issue / task board / repo；Anthropic 的样本说明，产品、设计、数据、法律、营销都可能变成 builder；Stripe 的样本说明，Agent 一旦进入支付和交易，商品、价格、授权、风控、履约都要机器可读；Block 的样本则提醒我们，AI-native 也可能滑向粗暴降本叙事。

我们的做法：把 Agent 当作可审执行层，而不是替公司做判断的黑箱。目标人定，过程可委托，结果可审计，失败要写回。

四个样本，各自代表一种协作模式

company modes
Control Plane

OpenAI：把任务变成 Agent 队列

Codex、Harness Engineering 和 Symphony 的共同点，是把工程工作从一次次交互 session 推向 issue、task board、repo knowledge、测试和 review。

  • 人定义目标和边界。
  • Agent 并行执行小块任务。
  • PR、测试、日志和 review packet 承接审查。
Builder Surface

Anthropic：让更多职能直接构建

Claude Code 的内部案例说明，Agent 不只服务工程。设计、数据、产品、法律和营销都可以把问题描述成可运行产物，再由人审查。

  • 设计可以把 mockup 变原型。
  • 数据人员可以生成可视化应用。
  • 职能专家仍负责语境、判断和验收。
Transaction Infrastructure

Stripe：让 Agent 能安全交易

Agentic commerce 不是按钮换入口，而是把商品、价格、库存、支付授权、风控、税务、履约和售后变成 Agent 能读、能调用、能审计的系统。

  • ACP 提供商家和 Agent 的共同语言。
  • SPT 避免暴露买家真实支付凭据。
  • MCP / metadata 让业务系统可被 Agent 理解。
Org Bet + Warning

Block：AI-native 不能只等于裁员

Block 的工程博客展示了 repo readiness、AI Champions、AI rules、自动 PR 和多 Agent 工作流；近期裁员和 Dorsey 话语又把组织风险推到台前。

  • 真实价值在作业系统升级。
  • 真实风险在士气、判断、客服和人类回路。
  • 不能把 AI 生产率直接等同于岗位可删除。

现有公司的人该怎么做

role actions

Product / PM：写可执行意图

  • 把目标、非目标、用户场景、验收标准写清楚。
  • 把会议、材料、需求整理成 Agent 可执行上下文。
  • 保留业务取舍，不把判断外包给模型。

Engineering / TL：建可审执行系统

  • 准备 repo rules、测试、权限、沙箱、CI 和回滚。
  • 让 Agent 输出 PR、日志、风险和待确认项。
  • 把失败写回 eval、lint、skill、wiki 或模板。

Design / Research：把品味变成样本

  • 沉淀用户语境、反例、状态流和体验红线。
  • 用可运行原型检查假设，而不是只交静态稿。
  • 审查 Agent 产物是否符合真实用户语言。

Manager：管吞吐，也管后果

  • 不要只看用了多少 AI，要看可评审结果和返工原因。
  • 区分可委托执行与必须人类负责的判断。
  • 把组织缩编叙事和作业系统升级分开评估。

我们的 30 天落地链路

local operating loop
01 Intent一句话写清目标、读者、场景和不做什么。
02 Context把材料、源链接、现有页面、验收标准放到一个任务包。
03 Agent RunAgent 负责整理、草拟、实现、补测试或生成 review packet。
04 Human Review人审判断、边界、证据、风险和是否接受。
05 Writeback失败写回 wiki、eval、skill、lint、模板或流程。
不要先做“全公司 AI 转型”。先选一条真实链路：会议材料或需求进入，产出可审稿 / 可执行任务 / 可验证结果，再看返工是否下降、知识是否写回。
