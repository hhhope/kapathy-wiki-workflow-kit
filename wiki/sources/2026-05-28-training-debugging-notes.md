## 中文摘要

这次培训主要围绕“接入联调、问题排查、生产切换与验收闭环”。核心不是单点技术，而是一套排查方法：先确认接入边界和配置，再从网络、证书、SFTP/文件、网关路由、应用日志、数据库配置和业务结果逐层定位，最后通过变更、监控、验收、复盘形成闭环。

## 培训内容整理

### 1. 接入与联调准备

- 明确接入对象、业务诉求、交互方式和环境边界，先把“谁接谁、在哪个环境、通过什么链路、传什么数据”说清楚。
- 接入前需要准备并核对基础参数：商户号或机构号、IP、端口、域名或 DNS、网关配置、白名单、防火墙策略、SFTP 端点、证书、密钥、目录权限。
- 测试环境和生产环境要分开梳理，避免证书、域名、网关、白名单、路由、开关配置混用。
- 联调流程可按“申请接入 -> 网络/网关配置 -> 证书/密钥配置 -> SFTP 或接口连通 -> 测试验证 -> 生产验证 -> 验收归档”推进。

### 2. 问题排查方法

- 先判断问题属于哪一层：网络不通、权限不够、证书/密钥不匹配、SFTP 或文件异常、网关路由异常、应用逻辑异常、数据库配置异常、上游返回异常。
- 网络层重点看 IP、端口、DNS/域名解析、防火墙、白名单、网关路由和专线/链路状态。
- 认证层重点看证书、密钥、签名、有效期、环境是否匹配，以及测试证书和生产证书是否误用。
- SFTP/文件层重点看目录权限、上传/下载、落盘、`success` 或回执文件、解析结果、清算/对账/台账文件是否完整。
- 应用和网关层重点看请求日志、响应码、网关转发、Host/路由配置、批处理任务、开关状态和异常堆栈。
- 业务结果层重点看合同、台账、清算、对账、业务流水和上游回执是否能互相印证。

### 3. 常见调试案例

- SFTP 连不上或文件传输失败：优先核对白名单、端口、证书、密钥、目录权限、文件名规则、回执或 `success` 文件。
- 网关或链路不通：按“本地配置 -> 网络策略 -> 网关路由 -> 上游地址 -> 返回码/日志”逐段定位。
- 合同、台账、清算或对账口径不一致：不要只看单个页面结果，要同时核对合同记录、业务流水、清算文件、对账文件和上游回执。
- 商户号、机构号、Host 或路由配置错误：查看配置表、变更记录、网关日志和请求实际命中的链路，确认是否进错通道。
- 批量或定时任务异常：检查任务开关、执行时间、输入文件、落库/落盘状态、重复执行边界和补偿方案。
- 生产切换后异常：重点看变更项、回滚路径、监控指标、调用量、失败码、告警和业务验收结果。

### 4. 生产接入与变更验收

- 生产前需要形成检查清单：参数、证书、密钥、白名单、网关、SFTP 目录、业务开关、监控、回滚方案、联系人。
- 生产变更要明确窗口期、执行人、验证人、回滚条件和通知机制。
- 变更中要实时观察调用量、失败率、错误码、文件传输、批任务、清算/对账结果。
- 变更后要完成业务验收，并把异常、处理过程、最终结论记录下来。
- 对不确定项要及时拉齐产品、开发、运维、网络和上游机构，避免单线排查导致结论偏差。

### 5. 协同与沉淀

- 角色分工建议拆清楚：业务确认场景和验收口径，产品确认流程和边界，开发确认配置和代码逻辑，运维/网络确认链路和权限，上游机构确认地址、证书、白名单和回执。
- 排查过程要保留证据：原始请求、响应、日志、配置截图、文件样例、执行时间、错误码、处理人和结论。
- 培训后建议沉淀三类资产：
  - 接入联调 SOP：覆盖申请、配置、联调、生产、验收。
  - 故障排查 checklist：按网络、证书、SFTP、网关、应用、数据库、业务结果分层。
  - 案例库：记录问题现象、根因、处理动作、验证方式和避免复发的配置或流程改进。
