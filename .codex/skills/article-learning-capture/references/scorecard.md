# Article Learning Scorecard

Use this scorecard before deep reading.

## Score Bands

| Score | Action |
|---|---|
| 75-100 | Deep-read and write durable wiki notes |
| 60-74 | Brief-read and keep a candidate note |
| 0-59 | Record source and skip reason |

## Criteria

| Criterion | Points | What To Check |
|---|---:|---|
| Source credibility | 20 | Primary source, author/publisher credibility, publication date, stable URL |
| Evidence quality | 25 | Experiments, data, case details, logs, implementation details, reproducible observations |
| Local relevance | 25 | Clear impact on this repo, agent workflow, wiki method, output shape, or behavior assets |
| Transferability | 15 | Can become SOP, template, fixture, comparison, or concrete practice |
| Novelty vs existing assets | 15 | Adds something not already captured in current wiki/skills/OpenSpec |

## Hard Caps

Apply the lowest relevant cap after scoring:

| Condition | Maximum Score |
|---|---:|
| Original source cannot be accessed and user did not provide content | 40 |
| No credible author, publisher, or source chain | 55 |
| No evidence beyond opinion or generic advice | 65 |
| Low local relevance even if generally interesting | 59 |
| Duplicates existing repo learning with no new angle | 59 |
| Copyright boundary would require full verbatim reproduction to be useful | 59 |

## Required Score Record

Each scored article should record:

- total score
- score band
- per-criterion scores
- hard cap applied, if any
- decision: deep-read / brief-read / skip
- reason in one or two sentences

## Calibration Notes

- A famous source does not automatically score high.
- A practical article without data can still score well if it has concrete
  implementation detail and strong local relevance.
- A high-quality article can still be skipped if it does not affect the current
  repo or agent work.
- Do not use the score to hide uncertainty. If evidence is weak, mark the
  transfer point as candidate.
