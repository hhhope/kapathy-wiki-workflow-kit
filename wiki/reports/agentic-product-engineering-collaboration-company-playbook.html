AI Agent Collaboration / Evidence Newspaper Draft 03 · 2026-05-11

四家公司看 Agent 协作怎么落地

这不是“大家都用 AI 工具”的故事。OpenAI、Anthropic、Stripe、Block 展示的是四种不同战略：agent-first 工程操作系统、human-AI 协作工作空间、agent-readable 商业协议、AI-native 组织制度和风险。

判断一家公司的 Agent 协作现状，先看战略，再看行为：它把哪些工作交给 agent，哪些判断留给人，哪些系统边界被改造成可执行、可验证、可追责。

OpenAI 的重点不是“派任务给 agent”，而是把研发系统本身改造成 agent 可读、可运行、可自审的操作系统。Anthropic 的重点不是“非工程师也写代码”，而是把 Claude 放进专业团队的真实工作流，让专家和 AI 共同生产 artifact。Stripe 的重点不是“聊天里买东西”，而是重写 agent 交易时代的支付、授权、风控和履约协议。Block 的重点不是“工程师用了 AI”，而是把 AI-native 组织制度化，同时暴露把效率叙事和裁员绑定的风险。

OpenAI公开写作强调“Humans steer. Agents execute.”，并把 repo、CI、review、observability、docs 变成 agent 工作系统；Codex hiring 补强平台化信号。
Anthropic公开案例覆盖 data infra、product、security、marketing、design、legal；Claude Code best practices 把协作写成 explore、plan、verify、delegate 的工作法。
StripeInstant Checkout、ACP、SPT 显示交易协作从网页界面转向 agent、用户、商家、支付网络之间的协议链。
Block工程博客给出 95% 工程师使用 AI、50 名 Champions、自动 PR 21 倍增长；公开报道显示 4000/10000 裁员。

四个样本，各自代表一种协作模式

company modes / 组织信号
Agent-first OS

OpenAI：研发系统先为 Agent 重写

战略不是让 agent 接更多 ticket，而是把工程环境、知识、测试、review、observability 和架构约束改造成 agent 可以长期执行的操作系统。

Collaborative Workspace

Anthropic：专业工作流里嵌入 Claude

战略不是把所有人改造成工程师，而是让不同职能在自己的工作流里和 Claude 共同探索、生成、验证和迭代。

Transaction Protocol

Stripe：交易协议先对 Agent 可读

战略不是在支付页加 AI，而是让商品、授权、风控、结算、履约和售后成为 agent 能调用、商家能控制、平台能审计的协议。

Org System + Warning

Block：AI-native 组织制度和缩编叙事并存

战略是把 AI adoption 变成工程制度、培训、上下文和指标；风险是这种制度升级被管理层直接翻译成更小团队和裁员逻辑。

四家公司：从战略下钻到协作行为

strategy → behavior → collaboration

OpenAI

路径：从 coding assistant 走向 agent-first engineering operating system。

战略选择

OpenAI 的公开写作把战略说得很清楚：当 agent 能写代码，工程团队的主要工作就不再是手写实现，而是设计环境、指定意图、建立反馈回路，让 Codex 能可靠工作。

证据：Harness Engineering
公开行为与协作方式
  • 5 个月约 100 万行代码、约 1500 个 PR，早期 3 名工程师驱动 Codex，后扩大到 7 名。
  • Symphony 把 Linear 这类 issue tracker 变成控制面：每个 open task 对应一个 agent workspace，系统持续 watch task board，agent crash 或 stall 时重启。
  • Symphony 还处理 CI、rebase、conflict、flaky check retry 和 handoff；它是 reference implementation，不等同于 OpenAI 全部战略，但暴露了协作机制。
  • repo 知识成为 system of record，短 AGENTS.md 作为入口，docs、plans、product specs、quality docs 分层承载上下文。
  • Codex 直接使用 gh、local scripts、repository-embedded skills，自己 review、响应反馈、修复构建失败并推进 PR。
  • UI、logs、metrics、traces 对 Codex 可读，agent 可以复现 bug、驱动浏览器、查询观测数据、再次验证。
  • 架构约束、taste invariants、custom lint、结构测试把人的判断编码成可重复执行的系统。
招聘/JD 信号

OpenAI Careers 搜索 Codex 显示 25 个岗位。Core Agents JD 关注 sandbox、isolation、orchestration、stateful workflows、memory、production fleet、CI/CD、安全和开发平台，说明它在补 agent 执行系统的基础设施，不是只招会写 prompt 的人。

我们学到

先别问“任务能不能进队列”。更大的问题是：我们的知识、环境、测试、观测、review 和失败写回，是否已经变成 agent 能读、能跑、能验证、能改进的工程系统。

Anthropic

路径：把 Claude 做成专业团队日常工作流里的协作者。

战略选择

Anthropic 的战略不是把 Claude Code 包装成单一研发工具，而是让 Claude 进入不同职能的具体工作流。人仍然拥有专业判断，Claude 负责探索、生成、自动化和验证。

证据：How teams use Claude Code
公开行为与协作方式
  • Infrastructure 的新数据科学家让 Claude Code 读取 CLAUDE.md，解释 pipeline dependency，并说明哪些 upstream sources feeding dashboards。
  • Data Infrastructure 在 Kubernetes incident 中把 dashboard screenshots 交给 Claude Code，定位 pod IP exhaustion，并拿到具体补救命令。
  • Growth Marketing 构建广告 CSV 处理和 Figma plugin 工作流，用 specialized subagents 生成大量广告变体。
  • Product Design 用 Claude Code 做 prototype、写 tests、检查 edge cases，把设计假设变成可运行 artifact。
  • Legal 做 phone tree 和自助审核工具，说明协作已经进入专业服务流程，而不只是工程研发。
  • Claude Code best practices 强调 explore first、plan、verify、context management、permissions、MCP、subagents，这是一套协作方法而不是单个工具技巧。
招聘/JD 信号

Claude Code PM JD 要求候选人有 5 年以上 PM+工程经验，至少 1 年职业工程背景，并能和 research、engineering、XFN 团队一起把模型进展翻成产品能力。

我们学到

不要把它写成“职能专家能不能构建”。更准确的问题是：每个专业团队的工作流里，有没有让 AI 参与探索、生成、验证和迭代的位置，同时保留人的语境、品味和责任。

Stripe

路径：把交易从人类界面改造成 agent 可调用的经济基础设施。

战略选择

Stripe 把 agentic commerce 定义为新的经济基础设施问题。AI 入口变成 storefront 后，交易不再是人点击网页，而是 agent 带着用户意图、身份、支付上下文进入商家系统。

证据：ACP / SPT
公开行为与协作方式
  • ChatGPT Instant Checkout 先支持美国 Etsy 商家，Shopify 商家后续接入。
  • ACP 是 Stripe 与 OpenAI 共建的开放标准，目标是让商家用一次集成接入多个 AI agent。
  • Shared Payment Token 按 merchant 和 cart total 限定，避免暴露真实支付凭据，同时保留风控能力。
  • ChatGPT 把 token 和订单通过 API 交给商家，商家接受或拒绝订单，处理收费、税务、履约、退货。
  • 协作边界不是“agent 下单”一句话，而是用户、agent、商家、支付网络、风控、履约之间的责任链。
招聘/JD 信号

Agentic Commerce EM JD 明确写新 API primitives、dashboard surfaces、money movement、Stripe primitives 集成；Designer JD 明确面向 merchants、agents、consumers 三类界面。

我们学到

当协作跨出公司边界，最先要补的不是提示词，而是协议。凡是涉及钱、合同、客户承诺、履约和风险的流程，都必须先做到 agent 可读、可授权、可审计、可回滚。

Block

路径：一边做工程组织 AI-readiness，一边用 AI 解释组织缩编。

战略选择

Block 的公开材料显示两件事同时发生：工程侧把 AI adoption 制度化，管理侧把 intelligence tools 和 smaller team 绑定。这个样本必须同时保留正面做法和组织风险。

证据：Block Engineering + Guardian reporting
公开行为与协作方式
  • 约 95% 工程师定期使用 AI 辅助开发。
  • 50 名 Engineering AI Champions，每人投入 30% 时间做 enablement。
  • 3 个月内 AI-authored code +69%，reported time savings +37%，automated PRs +21x。
  • repo 层面设置 AGENTS.md、HOWTOAI.md、agent skills、AI rules、usage tracking、CI/CD 分析和 incident/postmortem 辅助。
  • 40,000+ source files、30,000+ test files、650+ deployable services 的 monorepo 被拆成 root context 和 service-level context。
招聘/JD 信号

当前 Block careers 页面显示 0 open jobs。这个实时招聘信号不能支持“Block 正在扩招 AI 岗位”的判断；本页只把它作为当前招聘边界，不从中推断具体原因。

我们学到

Block 的 repo readiness、champions、rules、skills、指标和自动 PR 值得学。不能学的是把 AI-native 直接翻译成“少人更好”。协作系统升级和裁员叙事必须分开判断。

这四条路给我们的判断坐标

what the evidence says

OpenAI：协作重心从写代码转向设计执行系统

如果我们的上下文、测试、观测、评审、架构约束还散在聊天和人脑里，agent 只会加速混乱。OpenAI 的启发是先把系统变成 agent 可读。

Anthropic：协作重心从交接转向共同生产 artifact

专业团队不只是把需求丢给工程。更好的模式是让专家在自己的语境里和 AI 一起探索、生成、验证，再把能运行的东西交给组织判断。

Stripe：协作重心从界面转向协议

只要流程涉及钱、客户承诺或外部责任，AI 协作就不能停在“帮我操作”。它必须进入可授权、可审计、可拒绝、可追责的协议层。

Block：协作重心从工具采用转向组织制度

采用率、champions、AI rules、skills、usage tracking 都是组织动作。但 Block 也提醒我们：把 AI enablement 和缩编绑定，会改变员工对协作系统的信任。

这页最终应该只留下一个启发

one usable takeaway

OpenAI 给的启发：先改系统，不先改口号

把 repo、测试、观测、review、执行计划和失败写回变成 agent 可读的系统，否则“让 agent 多做任务”只会放大上下文缺口。

Anthropic 给的启发：让专业流程产出 artifact

协作不是把需求转交给工程，而是在设计、数据、营销、法律等流程里让 AI 参与探索、生成、验证，最后由人判断是否接受。

Stripe 给的启发：跨系统协作先协议化

涉及钱、权限、客户承诺和履约时，agent 协作要先定义接口、授权、风控、拒绝、审计和回滚，而不是先让模型代人点击。

Block 给的启发：制度化要和裁员叙事切开

repo readiness、champions、rules、skills 和 metrics 可以学；把 AI-native 直接翻译成“更少的人”会伤害组织信任，必须单独作为风险处理。
